# Teacher Note Prompt v1

이 요청 메시지 자체는 분석 대상에서 제외하고, 이 요청 직전까지 진행된 대화만 정리해줘.

목적은 이 대화를 Entity Graph, Knowledge Graph, Action Item 목록으로 변환하는 것이 아니다. 시간이 지난 뒤 다시 읽어도 대화가 어떻게 시작되고, 어떤 질문과 답변이 이어졌으며, 사용자가 언제 조건을 추가하거나 수정하고 방향을 바꿨는지 이해할 수 있는 서술형 노트를 만드는 것이다.

다음 원칙을 반드시 지켜줘.

1. 대화의 시간 순서를 유지한다.
2. 처음 요청과 마지막 상태만 남기지 말고, 그 사이에 있었던 중요한 질문·답변·수정·전환을 보존한다.
3. 사용자가 조건을 변경하거나 앞선 요청을 철회했다면 다음처럼 변화 과정이 드러나게 쓴다.
   - 처음에는 무엇을 원했는가
   - 이후 무엇이 추가되거나 제외되었는가
   - 최종적으로 어떤 방향이 남았는가
4. assistant의 제안과 사용자가 확정한 내용을 구분한다.
5. 대화에 없는 사실, 의도, 감정, 결정, 추천, 다음 행동을 추측해서 추가하지 않는다.
6. 시스템 메시지, 도구 호출, 내부 추론, 작업 로그는 제외한다.
7. 원문 발화를 순서대로 복사하지 말고, 의미가 유지되는 자연스러운 서술형 문단으로 압축한다.
8. 정확한 표현 자체가 중요한 경우에만 짧게 인용한다.
9. 해결되지 않은 내용이 실제로 있을 때만 미해결 상태라고 표시한다.
10. 불필요한 Entity, Relation, Action Item, 키워드 목록을 만들지 않는다.
11. 짧은 대화는 억지로 여러 섹션으로 나누지 않는다.
12. 결과는 대화에서 주로 사용한 언어로 작성한다.

아래 형식을 정확히 사용해줘.

```text
[REFERENCE_NOTE]

# 대화 전체를 나타내는 구체적인 제목

## 개요

대화가 무엇에서 시작되었고, 어떤 흐름을 거쳐 어디까지 도달했는지 2~4문장으로 설명한다.

## 01. 첫 번째 맥락을 나타내는 제목

첫 질문과 그에 대한 핵심 응답을 자연스러운 서술형 문단으로 정리한다.

## 02. 다음 맥락을 나타내는 제목

추가 질문, 조건 추가, 수정 또는 방향 전환이 있었다면 이전 맥락과 어떻게 달라졌는지 드러나게 정리한다.

필요한 만큼 섹션을 추가하되 최대 8개를 넘지 않는다.

## 현재 도달한 상태

대화 마지막 시점에 확정된 방향, 완성된 결과 또는 남아 있는 상태를 2~4문장으로 정리한다. 대화에서 확인되지 않은 다음 행동은 추가하지 않는다.

[/REFERENCE_NOTE]

[EVALUATION_GUIDE]

## 반드시 포함해야 할 맥락

- 다른 모델의 요약에도 반드시 남아야 하는 내용을 최대 8개로 작성한다.
- 각 항목은 원문에서 직접 확인할 수 있어야 한다.

## 주요 수정 및 방향 전환

- `기존 방향 → 변경된 방향` 형식으로 작성한다.
- 명확한 수정이나 전환이 없다면 `없음`이라고 작성한다.

## 구분해서 표현해야 할 내용

- assistant가 제안했지만 사용자가 확정하지 않은 내용
- 사용자가 명시적으로 선택하거나 확정한 내용
- 아직 해결되지 않은 내용
- 해당 사항이 없다면 `없음`이라고 작성한다.

## 요약에서 주장하면 안 되는 내용

- 대화만으로 확인할 수 없거나 추론해야 하는 내용을 최대 5개로 작성한다.
- 특별히 경계할 내용이 없다면 `없음`이라고 작성한다.

[/EVALUATION_GUIDE]
```

출력 전 다음 사항을 스스로 확인해줘.

- 시간 순서가 뒤바뀌지 않았는가
- 사용자의 수정과 제외 요청이 빠지지 않았는가
- assistant의 제안을 사용자 결정으로 표현하지 않았는가
- 대화에 없는 사실이나 추천을 추가하지 않았는가
- 단순한 발화 목록이 아니라 다시 읽기 좋은 하나의 노트가 되었는가
