# Teacher Content Note Prompt v4

이 요청 메시지 자체는 분석 대상에서 제외하고, 이 요청 직전까지의 대화만
GPTMemory의 **주제 중심 계층형 요약**으로 정리해줘.

핵심 원칙은 다음과 같다.

> 내용이 먼저, 상태는 그다음, 근거는 필요할 때 펼친다.

다음 규칙을 지켜라.

1. 질문·설명·비교·근거·관점 변화처럼 대화의 실질적인 내용을 먼저 선별한다.
2. 발화를 시간순으로 다시 쓰지 말고, 의미가 응집되는 주제 1~5개로 합성한다.
3. 핵심 정리는 3~5개로 제한하고 주제별 본문으로 이동하기 위한 색인처럼 쓴다.
   주제 본문과 결론에서 같은 문장을 표현만 바꿔 반복하지 않는다.
4. 사용자 조건 수정과 방향 전환은 관련 주제 안에 보존한다.
5. Assistant의 제안은 사용자가 명시적으로 수락하기 전까지 결정이 아니다.
6. `다음에 할 일`에는 대화 종료 시점에도 남은 명시적 작업만 넣는다. 완료 여부가
   확인되지 않는다는 이유만으로 할 일을 만들지 않는다.
7. 질문에 답한 것 자체는 산출물이 아니다. 실제 파일·문서·코드·설정처럼 만들어진
   결과만 보조 정보의 산출물로 기록한다.
8. 대화에 없는 사실, 결정, 담당자, 기한, 후속 행동을 추측하지 않는다.
9. 시스템 메시지, 도구 호출, 내부 추론, 작업 로그와 Teacher 요청은 제외한다.
10. 짧은 대화를 억지로 여러 주제로 나누지 않는다.
11. `한눈에 보기`는 10초 판단용으로 짧게 유지하되, `주제별 정리`는 원문을 다시
    열지 않고 핵심 논리와 다음 작업을 이어갈 수 있을 만큼 충분히 설명한다.
12. 각 주제에는 원문에 있는 범위에서 핵심 주장뿐 아니라 이유, 비교한 선택지,
    구체적인 연구·실행 설계, 예시, 조건 변화와 주의할 한계를 보존한다.
13. 주제별 본문은 보통 3~7개 내용 블록을 허용하고 각 블록은 필요하면 2~4문장으로
    쓴다. 단, 길이를 채우려고 사실을 만들거나 같은 내용을 반복하지 않는다.
14. 연구·학습 대화에 실제 프로젝트 진행 상태가 없다면 `현재 도달한 상태` 같은
    메타 문장을 만들지 않는다. 상태는 구현·실험·제출·문제 해결처럼 실제 변화가
    근거로 확인될 때만 기록한다.
15. 제안과 결정의 구분을 상태 섹션뿐 아니라 모든 본문에 적용한다. Assistant가
    제안한 방법은 사용자가 수락하지 않았다면 확정형 동사로 쓰지 않는다.

아래 형식을 사용한다.

```text
> 상태: v4 의미 정답지 초안
> 근거 상태: sourceMessageIds 미부여
> 승인 상태: 사람 검수 전
> 평가 사용: 자동 점수화 금지

# 구체적인 제목

## 한눈에 보기

- 이 대화가 무엇을 다뤘는지
- 핵심적으로 무엇을 알게 됐는지
- 실제 프로젝트 상태가 확인되는 경우에만 어디까지 진행됐는지

## 핵심 정리

- 가장 중요한 내용 3~5개

## 주제별 정리

### 1. 대화에 맞는 주제 제목

핵심 주장과 설명, 중요한 이유·비교·연구 또는 실행 설계·방향 변화를 자연스러운
문단과 내용 블록으로 정리한다. 이 부분은 원문 없이도 작업을 재개할 수 있는 본문이다.

필요한 만큼 추가하되 최대 5개를 넘지 않는다.

## 결론과 확정된 결정

- 결론과 사용자가 확정한 결정만 구분해 기록한다.
- 해당 내용이 없으면 없다고 명시한다.

## 다음에 할 일

- 대화에 명시된 미완료 작업만 기록한다.
- 없다면 `명시된 후속 작업 없음.`이라고 쓴다.

## 남은 질문

- 실제로 해결되지 않았거나 완료 여부가 확인되지 않은 핵심 질문만 기록한다.

## 보조 정보

- 실제 산출물
- 검토 중인 중요한 제안
- 중요한 제약과 변경 이력
```

이 단계의 출력은 의미 선택을 검토하기 위한 초안이다. 실제 `sourceMessageIds`는
공유 대화를 cutoff까지만 다시 정제한 뒤 별도 절차로 부여하고, 사람이 원문과
대조해 승인하기 전에는 Golden 정답이나 자동 점수 입력으로 사용하지 않는다.

길이는 대화에 적응시킨다. 짧은 대화는 약 1,500~3,000자, 일반 탐색·계획은
3,000~5,000자, 긴 연구·기획 대화는 5,000~8,000자까지 허용한다. 이는 채워야 하는
분량이 아니라 내용 손실을 막기 위한 상한 범위다. `한눈에 보기`와 `핵심 정리`는
합계 1,200자 이내의 빠른 판단 영역으로 유지한다.
