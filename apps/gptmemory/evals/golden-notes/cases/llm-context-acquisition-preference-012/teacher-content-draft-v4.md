# LLM 맥락 획득 전략과 사용자 선호 비교 연구

## 한눈에 보기

- 맥락 개념의 문헌적 분류에서 출발해, LLM이 맥락을 얻는 방식에 따른 사용자 선호를 비교하는 연구 방향을 만들었다.
- 사용자는 비즈니스 성과 중심 접근을 거부하고 직접 입력·대화적 추출·상호작용 이력 기반 추론을 같은 조건에서 비교하기로 했다.
- 연구 공백과 Study 1·2 설계안은 제안됐지만 제목, 과업, 표본, 척도와 프로토콜은 확정되지 않았다.

## 핵심 정리

- 광범위한 맥락 문헌 탐색은 실제 LLM 응답을 바꾸는 사용자·과업·상황 정보라는 실험적 정의로 좁혀졌다.
- 사용자는 비즈니스 성과 중심 제안을 거부하고 직접 입력·대화적 추출·상호작용 이력 기반 추론을 비교하는 연구를 선택했다.
- 결과물 자체의 **응답 선호**와 맥락을 얻는 과정에 대한 **상호작용 선호**를 분리하는 것이 핵심 설계 원칙이다.
- 기존 연구는 세 전략의 동일 조건 직접 비교, 두 선호의 분리와 맥락 획득 실패·활용 실패의 구분이 부족하다는 공백이 제시됐다.
- 골드 맥락과 공통 스키마·생성기로 획득 방식 외 조건을 통제하고, 일반·전략·오라클 응답을 비교하는 실험안이 제안됐다.

## 주제별 정리

### 1. 맥락 개념의 확장

논의는 글, 상황, 대화, 개인 심리라는 네 영역에서 사람들이 맥락을 어떻게 파악하는지 문헌으로 정리하는 데서 시작했다. 글에서는 문장·문단의 담화 관계와 저자 의도, 상황에서는 목표·시간·장소·환경·제약, 대화에서는 발화 순서와 공동이해 갱신, 개인 심리에서는 기억·감정·정체성·신체 상태가 해석을 바꾸는 요소로 설명됐다.

후속 탐색에서는 장르·레지스터와 상호텍스트성, 문화, 사회적 역할, 활동·과업, 시간·역사, 공간·물질환경, 조직·제도, 플랫폼·미디어, 정보흐름·프라이버시, 선택·평가와 기술·AI까지 범위가 넓어졌다. 이는 맥락이 텍스트 내부 정보에 한정되지 않는다는 개념 지도를 만든 것이지, 모든 범주를 후속 실험의 독립변수로 채택한 것은 아니다.

LLM 연구로 좁힐 때는 초기 질의에 직접 드러나지 않지만 적절한 응답을 달라지게 하는 사용자·과업·상황 정보로 맥락을 한정하는 안이 제시됐다. 목표, 현재 수준, 시간·자원 제약, 출력 선호, 이미 시도한 내용과 이전 대화가 예시이며, 맥락의 양뿐 아니라 관련성·정확성·입력 부담·통제감·프라이버시 우려를 함께 보아야 한다는 설명이다.

### 2. 연구 방향의 전환

첫 논문화 시도에서는 서비스가 사용자의 텍스트·상황·심리·플랫폼 맥락과 얼마나 맞는지를 지각된 이해감, 신뢰, 만족, 구매·지속사용의도와 연결하는 디지털 비즈니스 연구가 제안됐다. 사용자는 이 방향이 지나치게 비즈니스 중심이라고 명시적으로 지적했다.

연구 단위는 기업 성과에서 한 사용자가 LLM과 상호작용하고 결과를 평가하는 과정으로 바뀌었다. 이후 사용자는 “LLM 상호작용에서 맥락 제공 전략이 응답 및 상호작용 선호에 미치는 영향: 직접 입력, 대화적 추출, 추론형 맥락의 비교”라는 제목과 방향을 직접 제시했다. 따라서 세 전략과 두 종류의 선호를 비교하는 중심 질문은 확정됐지만, ‘제공’ 대신 ‘획득’이라는 용어를 쓰자는 수정안은 Assistant의 제안으로 남아 있다.

### 3. 세 전략과 두 종류의 선호

직접 입력은 사용자가 목표·수준·제약·선호를 양식이나 프롬프트에 명시하는 조건이다. 대화적 추출은 LLM이 확인 질문을 통해 같은 정보를 얻는 조건이고, 추론형 맥락은 이전 상호작용 이력에서 시스템이 자동으로 추론하는 조건이다. 자동 추론 뒤 사용자에게 확인·수정 기회를 주는 방식도 후속 변형으로 제시됐다.

응답 선호는 조건 정보를 가린 채 어떤 최종 답변을 실제로 고르는지 측정한다. 반면 상호작용 선호는 입력 양식 작성, 확인 질문, 자동 추론과 같은 과정을 다시 사용하고 싶은지 평가한다. 더 좋은 답변을 만드는 방식이 더 편리하거나 신뢰받는 방식과 같지 않을 수 있으므로, 전체 만족도 하나로 합치지 않아야 한다는 논리다.

또한 맥락을 얼마나 정확하고 완전하게 얻었는지와, 얻은 맥락을 응답 생성기가 얼마나 잘 활용했는지를 분리해야 한다. 반복적으로 유지되는 안정적 선호와 현재 과업에만 적용되는 일시적 제약도 같은 방식으로 다뤄서는 안 된다는 연구 공백이 제시됐다.

### 4. 실험 설계 제안

본실험 전에 참가자의 실제 목표, 수준, 제약, 출력 선호, 회피 조건과 선행 경험을 수집해 ‘골드 맥락’을 만드는 절차가 제안됐다. 추론형 조건에 개인 ChatGPT 기록을 직접 제출하게 하기보다 연구 안에서 통제된 상호작용 이력을 생성해 개인정보와 데이터량 차이를 줄이는 방안이다.

Study 1은 참가자 내 설계로 세 전략을 비교하고, 전략과 과업의 순서 효과는 라틴 스퀘어로 통제하는 안이다. 각 전략이 얻은 정보를 목표·현재 상태·제약·출력 선호·회피 조건·선행 경험이라는 공통 스키마로 변환한 뒤 동일한 응답 생성기에 넣는다. 모델, 프롬프트, 길이와 형식을 고정해 맥락 획득 방식의 차이를 최대한 분리하려는 설계다.

각 과업에는 초기 질문만 쓴 일반 응답, 해당 전략이 얻은 맥락을 쓴 전략 응답, 사전 골드 맥락을 쓴 오라클 응답을 만든다. 일반 대 전략은 실제 맥락 획득의 효과, 전략 대 오라클은 획득 과정의 손실, 오라클 대 일반은 해당 과업에서 가능한 맥락 효과의 상한을 비교하기 위한 구성이다. 블라인드 강제선택, 재사용 의향과 전략 순위 외에도 맥락 정확성·완전성·과잉추론·모순, 이해감·통제감·투명성·입력 노력·침해감을 측정하는 안이 제시됐다.

Study 2는 상호작용 이력에서 추론한 프로필을 숨기는 조건, 보여주되 수정할 수 없는 조건, 공개하고 수정·삭제할 수 있는 조건을 비교한다. 추론형 맥락에 대한 낮은 선호가 추론 자체 때문인지 투명성과 통제권 부족 때문인지 분리하려는 후속 설계다. 표본 수, 학습계획·글쓰기·일상 의사결정 과업, 척도와 혼합효과 분석법은 모두 제안 단계다.

## 결론과 확정된 결정

- **확정 방향:** 비즈니스 성과가 아니라 실제 LLM 상호작용을 연구한다.
- **확정 비교:** 직접 입력·대화적 추출·추론형 맥락을 비교한다.
- **확정 결과변수:** 응답 선호와 상호작용 선호를 구분한다.
- **주의:** ‘맥락 획득 전략’이라는 용어 수정과 Study 1·2 세부는 Assistant의 제안이다.
