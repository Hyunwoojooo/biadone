# M2·M4 맥미니 백업과 M4 환경의 M2 이전

## 한눈에 보기

- 두 맥미니의 환경을 물리적으로 교환하지 않고 Time Machine 백업과 마이그레이션으로 서로 옮기려 한 문제 해결 대화다.
- M2는 Samsung T7 외장 SSD에, M4는 공간 문제로 Synology NAS에 백업했고, NAS 복원 오류를 우회해 M4 환경을 M2로 옮기는 데 성공했다.
- 반대 방향 이전, 화면 공유 권한 오류와 SSH·Ghostty 매크로 구현은 완료가 확인되지 않았다.

## 핵심 정리

- 물리적 저장장치 교환 대신 Time Machine 백업과 Migration Assistant로 사용자 환경을 교차 이전하는 방식을 택했다.
- 외장 SSD 하나를 `M2`, `M4` APFS 볼륨으로 나눴지만, M4 백업은 용량 부족으로 Synology NAS로 변경됐다.
- 초기 설정 중 NAS 백업 마운트가 실패해 임시 계정으로 설정을 끝낸 뒤 Migration Assistant와 `.sparsebundle` 수동 마운트로 우회했다.
- 계정 충돌에서 임시 `joo` 데이터는 보존하지 않고 백업 계정으로 대치했으며, M4 환경이 M2로 정상 이전됐다.
- 터미널을 통한 아이폰 핫스팟 연결은 성공했지만 화면 공유 제어 권한과 키보드 매크로는 미확인 상태다.

## 주제별 정리

### 1. 백업 전략의 변경

목표는 M2의 기존 앱·계정·파일·설정을 M4로, M4의 환경을 M2로 옮기는 것이었다. Apple Silicon Mac의 내부 SSD나 부품을 물리적으로 바꾸는 대신, 각 환경을 Time Machine으로 백업한 뒤 반대편 Mac에서 Migration Assistant로 가져오는 방식이 선택됐다. 한쪽 복원이 성공하기 전에는 다른 Mac을 초기화하지 않는 순서도 유지됐다.

외장 저장장치가 Samsung T7 500GB 하나뿐이어서, GUID·APFS로 포맷한 하나의 컨테이너 안에 `M2`와 `M4` 볼륨을 만드는 구성이 사용됐다. 두 볼륨은 고정 파티션이 아니라 공간을 공유했고, 약 200GB가 필요하다고 본 M2 백업에는 약 250GB 한도를 두는 방안이 안내됐다. M2의 암호화된 Time Machine 백업은 이 외장 SSD에 정상 완료됐다.

같은 SSD에 M4를 처음 백업하자 공간이 거의 소진돼 대상이 Synology DS1821+로 바뀌었다. 처음에는 네트워크 디스크가 필요한 기능을 지원하지 않는다는 오류가 있었고, DSM에서 전용 공유 폴더·계정, SMB, Bonjour 서비스 검색, SMB 기반 Time Machine 브로드캐스트와 대상 폴더를 설정하는 절차가 안내됐다. 이후 `MIMIC_NAS.local`의 암호화된 네트워크 백업이 완료된 것이 확인됐다.

### 2. NAS 복원 실패와 우회

M2를 먼저 초기화한 뒤 설정 화면에서 NAS의 M4 백업을 찾았지만 백업 이미지를 마운트하지 못했다. Finder에서는 공유 폴더와 `.sparsebundle`이 보였으므로 네트워크·계정·암호, 원본 M4의 파일 사용 상태, SMB 주소, 권한과 잠금 가능성이 점검 대상으로 제시됐다. 이 가운데 어느 하나가 최초 실패의 원인이라고 확정되지는 않았다.

사용자는 초기 설정 단계에서는 데이터 이전을 건너뛰고 임시 계정을 만들어 macOS 설정을 마쳤다. 이후 Finder에서 NAS의 `.sparsebundle`을 직접 열자 백업 볼륨이 생겼고, Migration Assistant가 같은 이미지를 다시 열 때 “이미 사용 중”이라고 표시됐다. 수동 마운트·NAS 연결 상태를 정리하고 macOS 안에서 Migration Assistant를 다시 실행하는 우회 흐름으로 전환됐다.

이전 과정에서는 임시로 만든 `joo` 계정과 백업 안의 같은 이름 계정이 충돌했다. 사용자는 임시 계정 데이터가 필요 없다고 했고, 백업 계정으로 대치하되 임시 데이터 복사본을 남기지 않는 선택이 안내됐다. 이후 사용자가 M4 환경이 M2로 잘 옮겨졌다고 확인했다. 다만 기존 NAS 백업을 새 M2가 이어받을지 묻는 화면에서 어떤 항목을 선택했는지는 확인되지 않았다.

### 3. 원격 제어와 매크로

M4 환경을 옮긴 뒤 마우스 없이 맥북 트랙패드로 맥미니를 제어하는 문제가 이어졌다. Universal Control과 화면 공유가 먼저 언급됐지만, 맥미니에 마우스도 기존 Wi‑Fi 연결도 없다는 조건이 추가됐다. `networksetup`으로 실제 Wi‑Fi 인터페이스를 확인해 아이폰 핫스팟에 연결하는 명령이 안내됐고, 사용자는 연결 성공을 확인했다.

화면 공유를 켜기 위해 `ARDAgent`의 `kickstart`와 실제 네트워크 장치의 IP 확인 방법이 제안됐다. 접속 시 “사용자가 본인의 화면을 제어할 수 없습니다”라는 권한 오류가 나타났고, 원격 관리 권한을 다시 부여하는 추가 명령이 제시됐지만 해결 확인은 없었다.

마지막에는 MacBook·DGX·Gigabyte로 SSH 접속하는 세 기능과, 이미 MacBook에 SSH 접속된 Ghostty 창을 앞으로 가져오는 기능이 구체화됐다. Shortcuts에서 AppleScript를 실행하고 창 ID를 파일에 기록해 다시 활성화하는 구성이 제안됐으나 실제 생성·테스트는 확인되지 않았다.

## 결론과 확정된 결정

- **확정된 결과:** M2 백업은 외장 SSD에, M4 백업은 Synology NAS에 완료됐다.
- **확정된 결과:** M4 사용자 환경과 데이터가 M2로 정상 이전됐다.
- **확정된 결과:** 터미널을 이용한 Wi-Fi 연결에 성공했다.
- **주의:** 양방향 교차 이전 전체가 끝난 것은 아니다.
