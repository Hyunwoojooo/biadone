# Biadone Studio 기술 설계

상태: 구현 및 검증 기준. 이 문서의 요구사항은 동작 검증 결과를 의미하지 않는다. 실제 확인한 범위는 구현 완료 후 QA 기록에 남긴다.

이 문서는 [CONTRACT.md](./CONTRACT.md)의 데이터·명령·HTTP 계약과 [DESIGN.md](./DESIGN.md)의 화면 기준을 설명한다. 세부 필드와 API의 기준은 `CONTRACT.md`이며, 변경 시 구현·테스트·이 문서를 함께 맞춘다.

## 1. 제품 목표와 범위

개인 Mac에서 나레이션을 중심으로 롱폼 설명 영상을 제작한다. 사용자가 직접 장면을 구성하고, 일관된 템플릿으로 편집하며, 저장한 프로젝트를 다시 열어 필요한 부분만 수정할 수 있어야 한다.

- 기본 형식: 16:9, 1920×1080, 30fps.
- 주 사용 길이: 5~30분. 짧은 검증 프로젝트도 허용하며, 지원 대상 길이와 실제 출력 검증 길이를 구분한다.
- 실행: 브라우저 편집 화면과 `127.0.0.1:4317`의 로컬 Node 서버.
- 입력: 음성, 이미지, 영상, SRT/VTT, 시간 정보가 있는 전사 JSON.
- 출력: H.264 MP4, 음성이 있는 경우 AAC, 자막 SRT/VTT, 프로젝트 JSON 및 출력 검증 정보.
- 화면 유형: `title`, `quote`, `compare`, `steps`, `list`, `stat`, `flow`, `media`, `character`이며, `media`의 이미지·영상을 구분해 사용자에게 10종으로 표시한다.
- 편집 AI: 별도 OpenAI API나 API 키를 사용하지 않는다. 장면 생성은 기존 로그인으로 Codex CLI를 실행해 구조화된 장면 초안을 받고 검증·검토 후 적용한다. 선택적인 로컬 MCP 조작도 지원한다.

첫 버전은 원본 나레이션을 자르거나 무음을 삭제하지 않는다. 장면 경계를 바꾸어도 음성의 시간축은 유지한다. 복잡한 다중 트랙 오디오 편집, 생성형 영상 서비스, 정교한 립싱크, 임의 코드 실행과 외부 편집기 프로젝트 변환은 별도 확장 범위다.

## 2. 제작 파이프라인과 화면

| 단계 | 사용자 작업 | 저장·검증할 결과 |
|---|---|---|
| 01 소스 준비 | 프로젝트 생성, 음성·미디어 가져오기, 로컬 전사 또는 자막 가져오기 | 실제 음성 길이, 자산 정보, 단어·자막 시간, 전사 상태 |
| 02 장면 구성 | 챕터·장면 추가, 대본 구간 선택, 유형·필수 요구 지정, 개별·전체 생성 및 인라인 검토 | 전체 나레이션 시간축과 영구 요구사항을 가진 장면 카드 |
| 03 생성 결과 | 보관 초안 미리보기·적용 | 원본 리비전·장면 범위·검증된 초안·작업 상태 |
| 04 편집 | 화면 유형·문구·미디어·동작 조절, 장면 분할·병합·잠금 | 미리보기와 동일하게 출력할 편집 데이터 |
| 05 검수 · 출력 | 품질 문제 확인, 경고 검토, 출력 시작·진행 확인 | 출력 파일, 사용한 리비전, 성공·실패와 검증 결과 |

화면은 `assets/editor-concept.png`를 기준으로 밝은 회색 작업면, 흰 패널, 짙은 글자, 녹색 선택·실행 상태를 사용한다. 왼쪽은 장면·챕터, 가운데는 16:9 미리보기와 나레이션·자막 편집, 오른쪽은 속성·스타일·검수, 아래는 챕터·장면·실제 음성 파형·자막 타임라인이다.

재생 위치, 타임라인 헤드, 선택한 장면과 자막이 같은 시간축을 사용해야 한다. 저장·전사·품질·출력 상태는 실제 결과만 표시하며, 예제 제목이나 시간으로 완료 상태를 꾸미지 않는다. 데스크톱 기준 외에 1280px 폭과 좁은 화면에서 패널 스크롤·서랍으로 편집 접근을 유지한다.

## 3. 구성요소와 책임

| 영역 | 위치·후보 | 책임 |
|---|---|---|
| 앱 화면 | `src/`, React·TypeScript | 프로젝트·장면 선택, 폼 편집, 재생·탐색, 작업 상태 |
| 공유 계약 | `src/shared/`, Zod | 프로젝트·명령·출력 옵션의 구조와 입력 한도 검증 |
| 편집 도메인 | `src/domain/` | 명령 적용, 장면 시간 계산, 자막 파싱·그룹화, 품질 검사 |
| 로컬 서버 | `server/`, Express | 파일 가져오기, 저장·리비전·작업 관리, 루프백 HTTP API |
| 로컬 전사 | Python·faster-whisper | 기존 로컬 모델로 단어 시간 정보를 생성하고 구조화된 진행 상태 반환 |
| 영상 구성 | `src/video/`, Remotion | 프레임 기준 장면·자막·음성 구성, 템플릿·로컬 폰트 |
| 출력 | `server/render.ts`, Remotion·FFmpeg | 스냅샷 출력, 취소, 최종 파일 디코딩·메타데이터 검증 |
| Codex 연결 | `server/mcp.ts`, MCP SDK | 허용된 로컬 HTTP 기능을 stdio MCP 도구로 제공 |

React와 Remotion을 사용해 편집 미리보기와 출력 화면의 구성을 공유한다. Express는 로컬 파일·작업 API, Zod는 UI·HTTP·MCP 입력의 공통 검증, FFmpeg는 미디어 검사와 출력 검증에 사용한다. Noto Sans KR은 로컬 패키지로 제공해 한글 렌더링과 오프라인 동작을 일정하게 유지한다. 정확한 의존성은 `package.json`과 잠금 파일에 따른다.

기존 Edu의 음성·슬라이드·결과 영상과 `.video-build` 산출물은 원본으로 보존한다. 기존 로컬 Python 환경과 모델을 탐지해 사용할 수 있지만 고정 입력을 덮어쓰는 기존 제작 스크립트를 그대로 실행하지 않는다. 앱의 새 데이터는 `editor/data/` 아래에 저장한다.

## 4. 프로젝트와 시간 모델

프로젝트는 자산, 단어, 자막, 챕터, 장면, 전역 화면·음성 설정과 리비전을 관리한다. 자막 한 줄과 장면 한 개는 서로 다른 단위다. 한 장면 안에서 여러 자막이 바뀔 수 있다.

- 프로젝트 타임라인은 정수 프레임을 사용한다. 전사 `Word`의 시작·종료만 음성 기준 초 단위이며, 변환은 프로그램이 수행한다.
- 장면은 `[0, durationInFrames)`를 빈틈과 겹침 없이 나눈다. 자막의 종료 프레임은 포함하지 않는다.
- 장면·자막·챕터·자산·단어 ID는 안정적으로 유지하며 중복을 허용하지 않는다. 시간과 숫자는 유한하고 입력 한도를 만족해야 한다.
- 원본 나레이션은 전체 영상에 한 번만 연속 배치한다. 장면별 음성 복제로 경계마다 중복 재생하지 않는다.
- 영상 자산은 나레이션 아래에서 원본 소리를 음소거한다. 미디어 시작 지점과 `contain`/`cover`는 장면 설정으로 관리한다.
- `setNarration`은 실제 음성 길이에 맞춰 프로젝트 종료를 조절한다. 자막 범위가 맞지 않으면 검수 문제로 드러내며 전사 성공을 만들어내지 않는다.

장면 그룹화는 문장부호와 목표 길이를 이용한 결정적 규칙이다. AI 의미 분석이라고 표시하지 않는다. SRT/VTT와 faster-whisper `segments[].words` JSON을 공통 자막·단어 모델로 가져온다.

## 5. 편집 명령, 저장과 복구

UI와 MCP는 `EditorCommand`를 사용한다. 클라이언트가 프로젝트 JSON을 임의로 덮어쓰는 경로를 만들지 않는다.

1. 클라이언트는 현재 프로젝트와 `revision`을 읽는다.
2. 서버는 명령과 `expectedRevision`을 검증한다.
3. 프로젝트별 변경을 직렬화하고 도메인 규칙으로 적용한다.
4. 이전 상태를 리비전으로 보존하고 새 상태를 원자적으로 저장한다.
5. 저장된 프로젝트와 새 리비전을 반환한다.

리비전이 오래되면 HTTP 409를 반환한다. 화면은 충돌을 알리고 최신 상태를 다시 읽어야 하며, 오래된 값을 자동으로 덮어쓰지 않는다. 실행 취소·다시 실행·리비전 복원에도 같은 충돌 검사를 적용한다. 자동 저장 표시와 저장 실패 표시는 서버의 실제 응답을 따른다.

잠긴 장면은 내용 수정, 경계 이동, 분할·병합, 재그룹화를 거부하고 명시적 잠금 해제는 허용한다. 전역 테마와 타임라인 자막의 영향 범위는 장면 데이터 잠금과 구분해 구현·테스트에서 확인한다. 잠금을 전역 스타일까지 고정하는 기능으로 설명하지 않는다.

프로젝트 저장 위치는 `data/projects/<id>/project.json`, `assets/`, `revisions/`다. 자산 파일명과 참조는 프로젝트 경계 안에 머물러야 한다. JSON 다운로드는 미디어 복사본을 포함하는 패키지와 다르다. 이식 가능한 프로젝트 아카이브는 실제 지원·복원 검증 후에만 제공된다고 표시한다.

## 6. 전사·출력 작업

전사와 출력은 UI 요청과 분리한 지속 작업이다. 작업은 ID, 프로젝트 ID·리비전, 유형, 상태, 진행률, 메시지, 결과·오류 정보를 `data/jobs/`에 남긴다.

```text
queued → running → completed
                 → failed
queued/running   → cancelled
```

- 출력은 시작할 때의 프로젝트·자산 스냅샷을 사용한다. 이후 편집이 진행되어도 해당 출력이 최신 리비전의 결과인 것처럼 표시하지 않는다.
- 전사는 로컬 모델과 Python을 사용하며 실행 중 모델을 내려받지 않는다. 환경·모델이 없으면 이유를 표시하고 자막 가져오기·수동 편집은 계속 사용할 수 있게 한다.
- 전사 결과는 시작 당시 음성과 리비전이 여전히 맞을 때만 적용한다. 불일치하면 새 편집을 덮어쓰지 않고 검토·가져올 수 있는 결과로 취급한다.
- 취소는 상태 표시만 바꾸지 않고 실제 Python·렌더 작업에 전달한다. 실패·취소 결과는 남기며 재시도는 새 작업 ID로 추적한다.
- 앱 재시작 시 소유 프로세스가 사라진 실행 작업을 완료로 표시하지 않는다. 중단 사유를 남기고 재시도할 수 있게 한다.
- 과거 스냅샷과 현재 프로젝트 중 무엇을 재시도하는지 작업 유형별 정책과 화면 메시지로 드러낸다.

## 7. 일관된 화면과 출력

`VideoComposition` 하나를 Remotion Player와 최종 렌더러가 사용한다. 화면 비율, 글꼴, 줄바꿈, 템플릿과 등장 시점의 계산을 별도로 복제하지 않는다. 동작은 프레임으로 결정하고 렌더마다 달라지는 난수·현재 시각·온라인 자산을 사용하지 않는다.

- `sage`, `ink`, `sand` 테마와 공통 여백·강조색·글자 크기를 제공한다.
- 여섯 템플릿은 제목·본문·항목 수의 한도와 텍스트 배치 규칙을 갖는다.
- 한글/CJK 줄바꿈, 자막 안전 영역, 가독성을 고려한 축소·줄 수 제한을 사용한다.
- 캐릭터는 코드로 만든 간단한 숨쉬기·눈깜빡임·입 움직임이다. 음소 단위의 정교한 립싱크로 설명하지 않는다.
- 원본 나레이션의 음량 조절과 선택적 정규화는 프로젝트 설정으로 고정한다.
- 기본 출력은 1080p이며 출력 옵션의 720p는 같은 구성을 낮은 해상도로 렌더링한다.
- 출력은 H.264 MP4, 존재하는 음성의 AAC, faststart를 사용하고 예상 해상도·FPS·길이와 실제 파일을 비교한다.

부분 범위 출력은 전체 출력과 구분한다. 이전 장면·공통 테마·폰트 변경의 영향을 고려하지 않은 장면 캐시를 완성 기능으로 가정하지 않는다. 첫 버전은 저장된 장면을 선택 수정하고 안정적으로 재출력하는 흐름이 우선이다.

## 8. 품질 게이트

검수는 구조·파일·출력의 객관적 문제를 찾는다. 이야기의 전달력이나 연출의 취향까지 자동 보장한다는 뜻은 아니다.

| 검사 영역 | 확인할 내용 | 처리 |
|---|---|---|
| 시간축 | 유효한 프레임, 전체 장면 범위, 빈틈·겹침 | 오류는 출력 차단 |
| 템플릿 | 제목·본문·항목의 길이·개수와 필요한 필드 | 계약 규칙에 따른 오류·경고 |
| 자막 | 표시 시간, 겹침·공백, 길이와 안전 영역 규칙 | 수정 가능한 위치·대상 표시 |
| 자산 | 파일 존재, 종류·참조 일치, 사용할 영상 길이 | 누락·잘못된 참조 차단 |
| 음성 | 실제 나레이션 연결·길이와 프로젝트 범위 | 음성 없음은 경고, 전사 성공과 구분 |
| 출력 파일 | 스트림, 해상도·FPS·길이, 전체 디코딩 | 검증 실패는 출력 성공 처리 금지 |

오류가 있으면 출력하지 않는다. 경고만 있으면 사용자가 확인한 뒤 `allowWarnings`로 출력할 수 있다. 검사 결과에는 프로젝트에서 바로 찾을 수 있는 장면·자막 ID와 한국어 설명을 포함한다.

최종 파일의 자동 검사와 사람의 확인을 구분한다. 음성 내용과 자막의 의미 일치, 한글 가독성, 강조 타이밍과 연출 자연스러움은 대표 샘플을 직접 확인해야 한다. 수치 허용 오차와 확인 구간은 QA 실행 시 기록한다.

## 9. 로컬 Codex MCP와 접근 경계

MCP는 `list_projects`, `get_project`, `edit_project`, `get_quality`, `import_captions`, `start_export`, `get_job`을 제공한다. stdio 서버가 허용된 루프백 HTTP API만 호출하고 파일 저장 잠금이나 리비전 검사를 우회하지 않는다.

Codex는 프로젝트와 현재 리비전을 먼저 읽고, 잠긴 장면을 보존하고, 출력 전 검수하며, 작업이 실제 종료될 때까지 결과를 확인해야 한다. 작업 시작 응답은 출력 완료의 증거가 아니다. 읽기 도구는 읽기 전용으로 표시한다.

프로젝트 범위 설정 예시와 연결 설명만 제공한다. 사용자의 전역 Codex 설정을 자동 변경하거나 외부로 배포하지 않는다. 로컬 MCP 사용은 별도 OpenAI API 키 설정을 요구하는 에디터 기능과 구분한다.

서버는 루프백에 바인딩하고 Host·Origin과 같은 출처의 변경 요청을 제한한다. 브라우저가 임의 로컬 경로·셸 명령·외부 URL을 전달해 실행하거나 열 수 없게 한다. 업로드는 최대 2GB, JSON은 최대 8MB이고 자산은 스트리밍·메타데이터 검사·파일명 정제를 적용한다. 비밀값이나 `.env` 파일을 만들지 않는다.

## 10. 수용 기준

- 실제 저장 프로젝트에 음성을 가져오고 나레이션을 연결한다.
- 로컬 한국어 전사 또는 시간 자막 가져오기 후 문구를 고치고 장면을 구성한다.
- 챕터, 템플릿, 미디어, 자막, 장면 경계를 편집하고 잠금·실행 취소·복원을 확인한다.
- 저장 후 다시 열어 같은 상태와 미디어 참조를 복원한다.
- 검수 오류가 출력을 차단하고 경고 확인은 별도로 동작한다.
- 짧은 실제 출력의 전체 디코딩과 주요 미리보기 프레임의 일치를 확인한다.
- 실제 5분 이상 나레이션 프로젝트를 출력·검증한다. 20분 초과 타임라인 상태 테스트와 실제 장시간 출력 검증을 구분한다.
- 실행 중 작업 취소, 실패 후 재시도, 재시작 후 중단 상태 복구를 확인한다.
- MCP 초기화·도구 목록·프로젝트 조회·리비전 검사 편집을 실제 SDK 클라이언트로 확인한다.
- 1536px 데스크톱, 1280px 노트북, 좁은 화면에서 실제 편집 동작과 컨셉의 시각 기준을 검토한다.

상세 실행 순서와 QA 체크리스트는 [IMPLEMENTATION_PLAN.md](./IMPLEMENTATION_PLAN.md)에 둔다.
