# Biadone Studio 구현·검증 계획

상태: 현재 개인 Mac 환경의 구현·검증 완료. 체크는 소스 검사·회귀 테스트·실제 UI/미디어 검증 근거를 종합한 결과이며, 실행 범위와 한계는 [QA_REPORT.md](./QA_REPORT.md)에 기록한다. 다른 환경과 전체 30분 렌더까지 검증한 뜻은 아니다.

기준 문서: [기술 설계](./TECH_SPEC.md), [구현 계약](./CONTRACT.md), [화면 설계](./DESIGN.md). 기존 Edu의 원본과 결과물은 보존하고 새 구현은 `editor/` 안에 둔다. 별도 유료 API 호출·API 키·비밀 파일·외부 배포·전역 Codex 설정 변경은 포함하지 않는다.

## 1. 작업 소유권과 순서

| 작업 | 소유 영역 | 선행 작업 | 완료 조건 |
|---|---|---|---|
| T-001 앱 기반·계약 | Root: 패키지·설정·계약·통합 | 없음 | 작업자가 같은 타입·API·프레임 규칙을 사용하고 개발 명령이 정리됨 |
| T-002 도메인 | Domain: `src/shared/`, `src/domain/`, 관련 테스트 | T-001 | 모든 편집 명령·자막 파싱·그룹화·검수 규칙이 테스트로 확인됨 |
| T-003 저장·서버 | Server: `server/` 중 렌더 제외, Python 전사 보조, 서버 테스트 | T-001, T-002 계약 | 프로젝트·자산·리비전·작업이 지속 저장되고 충돌·경로 검사가 동작함 |
| T-004 영상 구성·출력 | Render: `src/video/`, `server/render.ts`, 관련 테스트 | T-001, T-002 계약 | 같은 장면 구성이 Player와 출력에 연결되고 실제 파일 검증·취소가 가능함 |
| T-005 편집 화면 | Root: 앱 화면·스타일·API 통합 | T-002~T-004 계약 | 소스부터 검수·출력까지 실제 UI로 이어지며 컨셉의 화면 구조를 유지함 |
| T-006 Codex MCP | Server·Root: stdio 연결·설정 예시·통합 검증 | T-003 명령 API | API를 우회하지 않고 SDK 클라이언트로 조회·편집·작업 확인이 가능함 |
| T-007 전체 QA | Root: 통합·브라우저·미디어 검증 | T-002~T-006 | 아래 체크리스트와 실제 검증 범위를 기록하고 미검증 항목을 드러냄 |

도메인·서버·렌더 작업은 계약을 공유해 병행할 수 있다. 파일 소유권을 유지하고 다른 작업자의 수정을 되돌리지 않는다. 계약 변경은 해당 소유자와 통합 담당자에게 전달하고 문서·소비 코드·테스트를 함께 조정한다.

## 2. 단계별 구현

### 단계 A — 로컬 처리 기반 검증

1. 기존 Python 환경, faster-whisper 모델, FFmpeg·ffprobe의 실제 탐지 결과를 확인한다.
2. 기존 고정 경로 제작 스크립트와 원본 산출물을 수정하지 않고 새 전사 어댑터에서 입력을 받는다.
3. 짧은 한국어 음성을 전사해 단어 시작·종료·누락·무음 주변 결과를 검토한다.
4. 공통 프로젝트로 짧은 장면을 렌더링하고 미디어 스트림·길이·프레임을 검증한다.

종료 기준: 로컬 환경이 없는 경우까지 포함해 사용자가 실행 가능 여부와 이유를 알 수 있다. 모델 존재·로딩 성공과 실제 전사 정확도는 별도 근거로 기록한다.

### 단계 B — AI 없이 끝까지 편집

1. 프로젝트 생성·목록·불러오기·원자적 저장·리비전·실행 취소를 연결한다.
2. 음성·이미지·영상 업로드와 나레이션 연결을 구분해 구현한다.
3. SRT/VTT/전사 JSON 가져오기, 자막 수정, 결정적 장면 그룹화를 제공한다.
4. 장면·챕터 목록, 미리보기, 속성, 실제 파형·자막 타임라인을 연결한다.
5. 여섯 템플릿, 공통 테마와 로컬 한글 폰트로 장면을 구성한다.
6. 장면 분할·다음 장면과 병합·경계 이동·잠금·복원을 제공한다.

종료 기준: 수동 조작만으로 실제 소스를 포함한 프로젝트 한 편을 구성하고 저장·재시작 후 동일하게 복원한다. 장면 경계 수정이 나레이션을 이동시키지 않는다.

### 단계 C — 검수·출력·작업 복구

1. 도메인 규칙과 서버 파일 존재 검사를 하나의 품질 결과로 표시한다.
2. 오류 출력 차단, 경고 확인, 관련 장면·자막으로 이동을 연결한다.
3. 렌더 시작 시 프로젝트·자산 스냅샷을 고정하고 진행률·리비전을 표시한다.
4. 실제 취소 신호, 실패 사유, 새 ID의 재시도와 재시작 후 중단 처리를 구현한다.
5. H.264/AAC·faststart 출력 후 메타데이터와 전체 디코딩을 검사한다.
6. 출력과 자막·프로젝트·QA 정보 다운로드를 실제 작업 결과에 연결한다.

종료 기준: 작업 시작, 실행, 실패·취소, 검증된 완료가 구분된다. 실패해도 프로젝트 편집 내용이 유지되며 오래된 작업 결과가 최신 상태를 덮어쓰지 않는다.

### 단계 D — 로컬 Codex 연결과 실제 한 편 완성

1. 로컬 stdio MCP가 HTTP의 프로젝트·명령·검수·출력·작업 API를 호출하게 한다.
2. 도구 설명에 리비전 확인, 잠금 보호, 검수, 완료까지 작업 확인 규칙을 넣는다.
3. 프로젝트 범위 연결 예시와 실행 방법을 제공하고 전역 설정은 자동 변경하지 않는다.
4. 실제 5분 이상 나레이션으로 편집·복원·출력 과정을 실행한다.
5. 긴 타임라인의 탐색·편집·상태 크기를 별도 검증하고 실제 렌더한 길이를 명시한다.

종료 기준: 수동 UI와 MCP가 동일한 명령·충돌 검사를 사용한다. 실제 영상 제작에 필요한 수정 흐름이 이어지고 검증 범위가 재현 가능하게 기록된다.

## 3. QA 체크리스트

### 도메인과 입력

- [x] 장면이 전체 프로젝트 프레임을 빈틈·겹침 없이 나눈다.
- [x] 잘못된 ID·중복 ID·NaN·무한대·음수·과도한 문자열·배열·프레임을 거부한다.
- [x] 분할·병합·경계 이동 후 전체 길이가 유지되고 나레이션 시간이 변하지 않는다.
- [x] 잠긴 장면의 내용·경계·분할·병합·재그룹화를 거부하고 잠금 해제는 가능하다.
- [x] 전역 테마·자막이 잠긴 장면에 미치는 범위를 실제 구현에 맞게 확인한다.
- [x] SRT/VTT, faster-whisper JSON과 앱 자막 JSON을 가져오고 시간·문구를 보존한다.
- [x] 한국어 줄바꿈, 긴 문구·항목 수, 짧은 자막과 겹치는 자막에 검수 결과가 나온다.
- [x] 음성 없이도 수동 프로젝트는 가능하며 전사·음성 존재 성공을 꾸며 표시하지 않는다.
- [x] 나레이션 교체로 길이가 변할 때 안전한 편집은 유지하고 부적합한 자막 범위를 드러낸다.

### 저장·파일·서버

- [x] 프로젝트 생성·자동 저장·재조회·프로세스 재시작 후 복원이 성공한다.
- [x] 실행 취소·다시 실행·과거 리비전 복원이 복구 가능한 기록을 남긴다.
- [x] 오래된 `expectedRevision`은 HTTP 409이고 최신 편집을 덮어쓰지 않는다.
- [x] 동시에 온 변경을 프로젝트별로 직렬화하고 불완전한 JSON 저장을 남기지 않는다.
- [x] 업로드한 오디오·이미지·영상의 종류·실제 메타데이터를 검사한다.
- [x] 경로 탈출, 외부 파일 참조, 잘못된 프로젝트·자산 ID와 과도한 입력을 거부한다.
- [x] 자산 Range 요청과 실제 미디어 탐색이 동작한다.
- [x] 루프백 Host·Origin 검사를 확인하고 외부 URL·셸 명령 실행 경로가 없다.
- [x] JSON 다운로드·가져오기와 미디어를 포함한 이식 패키지의 지원 범위를 구분한다.

### 전사·작업 관리

- [x] 로컬 Python·모델 유무를 실제로 탐지하고 실행 불가 사유를 표시한다.
- [x] 한국어 실제 샘플 전사와 단어 시간 정보를 확인한다.
- [x] 전사 중 편집·나레이션 교체 시 새 상태를 오래된 전사로 덮어쓰지 않는다.
- [x] 작업 진행률·오류 메시지가 실제 하위 작업에서 나온다.
- [x] 실행 중 작업 취소가 실제 프로세스·렌더에 전달된다.
- [x] 실패·취소 후 프로젝트를 열 수 있고 재시도가 새 ID로 추적된다.
- [x] 앱 재시작 후 남은 실행 작업을 중단으로 처리하고 완료로 표시하지 않는다.

## 4. 실행 명령과 기록

`editor/`에서 다음 스크립트를 사용한다. 실제 생성된 테스트·QA 스크립트의 내용과 실행 결과를 함께 확인한다.

```sh
npm run typecheck
npm run lint
npm test
npm run build
npm run qa
```

개발 실행은 `npm run dev`, 빌드 후 실행은 `npm start`, stdio MCP 실행은 `npm run mcp`다. 테스트나 QA 명령의 이름만으로 브라우저·전사·장시간 출력 검증까지 끝났다고 간주하지 않는다.

| 근거 단계 | 기록할 것 |
|---|---|
| 정적·단위 | 실행 명령, 통과·실패 수, 검사한 불변식 |
| 서버 통합 | 실행 주소, 저장·충돌·파일·작업 결과 |
| 브라우저 | 사용한 프로젝트, 화면 크기, 실제 수행 동작, 스크린샷·콘솔 문제 |
| 전사 | 실제 입력 길이, 모델·환경, 단어 시간 검토 구간과 한계 |
| 짧은 영상 | 프레임 수·스트림·길이, 전체 디코딩, 미리보기 비교 프레임 |
| 실제 롱폼 | 실제 음성·프로젝트 길이, 출력 소요 시간·완료 여부, 검증한 결과 |
