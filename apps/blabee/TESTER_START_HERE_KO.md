# Blabee 내부 테스트 — 먼저 읽어 주세요

2026-09-09 · 버전 0.1.0 / build 19 · Apple Silicon Mac용

이번 파일은 지정된 내부 테스터용입니다. Apple 공증 전이며 공개 재배포하지 않습니다.
Codex는 별도 설치가 필요합니다. Blabee가 Codex를 대신 설치하거나 구버전으로 바꾸지 않습니다.
패키지 검사와 설치 안내·사용 중 차단은 확인했지만, r19 설치 완료와 실제 연결 왕복은
아직 미검증입니다. 이번 파일은 그 확인을 위한 내부 테스트 후보입니다.

## 1. 압축 해제와 파일 확인

`Blabee-0.1.0-internal-arm64-20260909-r19-testers.zip`을 풉니다.
압축을 푼 폴더에서 터미널을 열고 아래 명령을 실행합니다.

```sh
shasum -a 256 -c CONTENTS.sha256
shasum -a 256 -c Blabee-0.1.0-internal-arm64-20260909-r19.dmg.sha256
```

모두 `OK`일 때만 설치합니다. 실패하면 파일을 고치지 말고 배포 담당자에게 다시 요청합니다.

## 2. 설치 또는 업데이트

- 처음 설치: DMG를 열고 안의 `Blabee.app`을 실행합니다. **Blabee 설치가 필요합니다**
  안내에서 **응용 프로그램에 설치하고 시작**을 누릅니다.
- 이미 설치: 기존 앱의 **macOS 자동 시작 서비스**가 등록돼 있을 때만 구버전 앱에서
  등록 해제합니다. Blabee를 사용하는 Codex 작업을 안전하게 마친 뒤 정상 종료하고,
  메뉴바 우클릭 → **Blabee 종료**를 선택합니다. 패널의 X는 종료 버튼이 아닙니다.
  DMG 앱을 실행해 원본 build `19`와 기존 build를 확인하고 **응용 프로그램에 설치하고 시작**
  → **백업하고 교체**를 선택합니다. r18 사용자도 최초 설치가 아닌 업데이트 테스트입니다.
- **관련 프로세스가 실행 중**이라는 안내가 나오면 교체를 강행하지 않습니다.
  Blabee 종료만으로 Codex에 연결된 MCP까지 종료되지는 않습니다. 관련 Codex를 정상 종료한
  뒤 **다시 확인**하고, 계속 차단되면 화면을 전달합니다. 강제 종료나 실행 중 앱 덮어쓰기는 하지 않습니다.
- 설치 완료 후 `/Applications/Blabee.app`의 build가 `19`인지 확인합니다.
  확인 방법은 [상세 가이드](INTERNAL_TEST_INSTALL_GUIDE.md#3-blabee-앱-설치하기)에 있습니다.
- 미공증 앱 안내가 나오면 [상세 설치 가이드](INTERNAL_TEST_INSTALL_GUIDE.md)의 macOS
  개별 앱 열기 절차를 따릅니다. 보안을 시스템 전체에서 끄지 않습니다. 회사 정책으로
  차단되면 우회하지 말고 테스트를 중단합니다.

## 3. Blabee 설정

메뉴바 Blabee 아이콘 → 오른쪽 위 **상자 버튼**을 누릅니다. 톱니바퀴는 단축키 설정입니다.

1. **관찰할 프로젝트**에 테스트할 프로젝트를 추가합니다.
2. **앱 실행형 서비스 켜기** → **서비스 연결됨**을 확인합니다.
   이미 켜져 있으면 반복하지 않습니다. **macOS 자동 시작 서비스 미등록**은 이 모드에서 오류가 아닙니다.
   다만 서비스 실행 중 프로젝트를 추가했다면 **서비스 다시 시작** 후 해당 프로젝트의
   **현재 서비스에서 활성** 표시를 확인합니다.
3. **Codex 연결하기** 또는 안내된 Plugin 업데이트 동작을 수행합니다.
4. 평소 사용하는 터미널에서 새 Codex 세션을 시작하고 `/hooks`에서 Blabee의
   `SessionStart`, `UserPromptSubmit`, `Stop`, `PermissionRequest`를 직접 검토합니다.

`Plugin 설치됨 · Hook 상태 확인`은 설치 실패 표시가 아닙니다. Hook 신뢰는 앱이 자동으로
확인하거나 대신 승인하지 않습니다. 소스 체크아웃, Orca, 별도 Codex 래퍼는 필수 사항이 아닙니다.

### ‘다시 검사’만으로 연결되지는 않습니다

- **Codex 연결하기**: Blabee Plugin을 설치합니다. **Plugin 업데이트**는 내장 Plugin으로 갱신합니다.
- **Codex 실행 다시 검사**: Codex와 Plugin 상태를 확인합니다. Plugin을 설치하지 않습니다.
- `result=plugin_not_installed`: 검사 대상 Plugin이 미설치 상태입니다. **Codex 연결하기**를 누릅니다.
- `error_code=none`: 검사 오류가 없다는 뜻이지 연결 완료라는 뜻이 아닙니다.
- 이미 **Codex 연결하기**를 눌렀는데 미설치라면 클릭 직후 상태·오류·시각과 새 검사 결과를
  보내 주세요. 이 로그만으로 설치 실패 원인을 알 수는 없습니다.
- `hook_trust=not_verified`와 `service_and_selection_roundtrip=not_tested_by_this_check`는
  별도 확인 항목입니다. Plugin 검사 성공으로 Hook 신뢰·서비스·선택 반환을 통과 처리하지 않습니다.

## 4. 이번에 확인해 주세요

- **Codex 실행 다시 검사**를 한 번 눌러 진행/완료 시각과 결과가 표시되는지 확인합니다.
- **진단 정보 복사**로 결과를 붙여 넣어 봅니다. 개인 경로나 비밀 정보가 없는지 확인한 후 전달합니다.
- 등록한 프로젝트에서 Codex에 다음과 같은 읽기 전용 작업을 요청합니다.

  > 파일과 설정을 변경하지 말고 현재 프로젝트의 최상위 파일 구성을 확인해서 간단히 설명해줘.
  > 이어서 할 수 있는 읽기 전용 확인 작업 두 가지도 제안해줘.

- 원래 답변이 끝난 뒤 Pet 카드가 나타나는지, 읽기 전용 선택지 하나를 누르면
  **같은 Codex 세션의 새 턴에서 해당 작업이 실제로 수행되는지** 확인합니다.
- 실패하면 반복 클릭하지 말고 시각·화면·검사 결과를 기록합니다.

### 명령 권한 카드 — r19 확인

이 카드는 답변 후의 다음 작업 제안과 별개입니다. 일반 `codex` 실행 방식을 그대로 사용합니다.
Codex 0.153.4 Apple Silicon의 검증된 서명/실행 경로에서만 **이번만 허용 · 거절 ·
Codex에서 직접 결정**이 표시됩니다. 다른 버전이나 검증되지 않은 연결에서는 뒤의 두 항목만
보이는 것이 정상입니다. 버전 번호만 같다고 반드시 승인 버튼이 나타나지는 않습니다.

- 권한이 필요한 안전한 읽기 전용 명령을 Codex가 요청할 때, 원래 요청과 Pet의 명령이 같은지 확인합니다.
- **이번만 허용**을 눌렀다면 전달 표시뿐 아니라 Codex의 실제 실행 결과를 확인합니다.
- 같은 권한 요청이 다시 생겼을 때 새 결정을 요구하는지 확인합니다. 자동으로 실행됐다고
  단정하지 않도록 기존 Codex 허용 규칙이 없는 테스트 상황에서 확인합니다.
- 별도의 요청에서 **거절**, **Codex에서 직접 결정**도 확인합니다. 권한 요청이 발생하지 않았다면
  강제로 보안 설정을 바꾸지 말고 `미실행`으로 기록합니다.
- **세션 위치**는 명령의 실제 실행 폴더/환경을 보증하지 않습니다. 실행 위치가 중요하거나
  명령을 충분히 이해하지 못했다면 **Codex에서 직접 결정**을 선택합니다.

이 실제 버튼 왕복은 테스터 확인 항목이며, 배포 전 완료된 검증으로 보고하지 않습니다.
앱/Plugin을 업데이트한 뒤에는 새 Codex 세션에서 `/hooks`를 다시 확인합니다.

구형 r15에서 Codex 버전이 고정됐던 사람은 상세 가이드의 **구형 셸 연결 정리**도 참고합니다.
직접 수정한 래퍼는 안전을 위해 자동 정리를 거부할 수 있습니다. 파일 삭제나 symlink 교체로
우회하지 말고 그 상태를 보고해 주세요.

종료: 메뉴바 Blabee 아이콘 우클릭 → **Blabee 종료**. 앱이 시작한 서비스도 함께 종료됩니다.
