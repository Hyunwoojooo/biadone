# Link Shelf — Blabee 촬영용 프로젝트

가칭: Link Shelf. 직전 추천인 개발자용 링크 보관함을 기준으로 진행한다.

현재 상태: **6A단계 완료 — Tools 필터 코드 추가, 브라우저 미확인**.
다음 단계: **6B단계 대기 — Tools 필터 브라우저 확인**.
Design 필터의 브라우저 확인을 통과했고, Tools 버튼과 해당 분류 렌더링 코드를 추가했다. Tools 동작의 브라우저 확인과 녹화는 시작하지 않았다.

## 진행 규칙

- 한 번의 사용자 요청에서는 현재 선택한 단계 하나만 진행한다.
- 각 단계의 결과와 확인 내용을 보고한 뒤 멈춘다. 다음 단계는 사용자의 다음 지시나 Blabee 선택을 받아 진행한다.
- 촬영 중 한 Codex 턴에서는 구현 한 조각 또는 확인 한 조각 중 하나만 진행한다.
- 구현과 브라우저 확인도 서로 다른 단계로 나누고, 각 조각이 끝날 때마다 문서 상태를 갱신한 뒤 Blabee 선택을 제출한다.
- 작업 범위는 `apps/blabee/recording-sandbox/link-shelf/`로 제한한다.
- 이 폴더는 촬영용 사본이다. 촬영이 끝난 뒤 폴더 전체를 삭제할 수 있도록 이후 소스 추가도 이 경로에서만 수행한다.
- 기존 `demo-site/`, Blabee 제품 소스, 공개 랜딩페이지는 이번 프로젝트 범위에 포함하지 않는다.
- 커밋·푸시·배포·실제 본편 녹화는 별도 요청이 있을 때 진행한다.

## 서비스와 촬영 목표

개발 중 발견한 문서·도구·디자인 참고 링크를 카드로 저장하고, 태그와 즐겨찾기로 다시 찾는 작은 웹앱을 만든다.

촬영에서는 사용자가 브라우저로 자료나 결과물을 보는 동안 Blabee에서 다음 작업을 선택하고, 같은 Codex 세션이 이어져 앱의 기능이 달라지는 모습을 보여준다.
앱 화면에 Blabee를 흉내 낸 선택 위젯을 만들지 않고 실제 Blabee를 사용한다.

## 최소 기능 범위

| 기능 | 사용자가 할 수 있는 일 | 완료 모습 |
| --- | --- | --- |
| 링크 추가 | 제목·주소·짧은 설명·태그를 입력한다. | 새 카드가 목록에 나타난다. |
| 태그 필터 | 태그 하나 또는 전체 보기를 선택한다. | 해당 태그의 카드만 보이고 전체 보기로 돌아갈 수 있다. |
| 즐겨찾기 | 카드의 별을 켜거나 끄고 즐겨찾기만 모아 본다. | 선택한 카드의 상태와 즐겨찾기 목록이 바뀐다. |

- 보조 동작: 추가한 링크와 즐겨찾기 상태를 같은 브라우저에 저장해 새로고침 후 복원한다. 저장 기능은 12~14단계에서 나눠 추가한다.
- 촬영 데이터: 직접 준비한 샘플 링크 6개. `Development`, `Design`, `Tools` 태그를 각 2개씩 배정한다.
- 초기 화면: 서비스 이름과 한 줄 설명, 샘플 링크 카드 목록. 기능 버튼은 해당 기능을 구현하는 단계에서 추가한다.
- 촬영안 기준 UI 문구는 짧은 영어로 작성한다. 기획과 진행 보고는 한국어로 작성한다.
- 구현은 HTML/CSS/JavaScript와 브라우저 저장 기능을 사용하는 독립적인 정적 웹앱으로 계획한다. 새 운영 의존성은 필요하지 않다.
- 로그인, 서버 데이터베이스, 외부 API, 링크 미리보기 자동 수집, 공유 기능은 범위에 포함하지 않는다.

4A~14단계는 구현과 확인까지 분리해 한 행씩만 진행한다. 15~18단계에서 결합 동작과 촬영 구도를 따로 확인한다.
실제 사용자 선택이나 녹화본 재생을 확인하지 못한 항목은 미검증으로 기록한다.

## 촬영에 남길 변화

1. 샘플 카드 목록을 브라우저에서 확인한다.
2. 실제 Blabee에 제안된 다음 작업 중 태그 필터 추가 같은 작은 개선을 선택한다.
3. 같은 Codex 세션이 이어지는 모습을 확인한다.
4. 앱에서 태그를 눌러 카드가 달라지는 결과를 보여준다.
5. 필요하면 즐겨찾기처럼 다른 작은 개선을 한 번 더 선택하고 결과를 사용한다.

선택지의 문구와 순서는 실제 Codex 제안에 맞춘다. 이 문서의 예시를 실제로 실행된 장면처럼 취급하지 않는다.
재촬영은 시작 상태의 별도 사본을 사용하며 기존 작업 디렉터리를 초기화하지 않는다.

## 1단계 확인 기록

- 서비스 범위와 최초 8개 단계의 완료 기준을 문서로 정리했다. 촬영 중 팝업 간격을 줄이기 위해 이후 작업을 구현과 확인 단위까지 다시 나눴다.
- 새 촬영 프로젝트 경로에 이 문서만 작성했다.
- 앱 코드, 기능 테스트, 브라우저 시각 확인, 실제 Blabee 선택 왕복, 녹화는 아직 수행하지 않았다.

## 2단계 설계 기준

- 전체 첫 화면 시안: [first-screen-concept.png](design/first-screen-concept.png), 원본 크기 1586 × 992. 내장 Image Gen으로 생성한 구현용 기준이며 사용자 시각 승인을 받은 상태는 아니다.
- 생성 프롬프트: [first-screen-concept.txt](design/first-screen-concept.txt).
- 배경은 따뜻한 아이보리 `#f6f5f1`, 카드는 흰색, 기본 글자는 `#242925`, 경계선은 `#ddded5`를 사용한다.
- 제목과 카드 이름은 시스템 Georgia 계열 세리프, 설명과 도메인은 시스템 sans-serif로 구성한다. 별도 폰트나 이미지 요청은 하지 않는다.
- 넓은 화면은 카드 3열 × 2행, 중간 화면은 2열, 좁은 화면은 1열이다. 카드 모서리는 16px, 카드 간격은 약 28px이며 외부 링크 화살표는 가는 선의 SVG 아이콘이다.
- 고정 문구: `Link Shelf`, `A little home for the links worth keeping.`, `Your collection`, `6 links`.
- 카드 순서: MDN Web Docs / Figma / Raycast / JavaScript.info / Google Fonts / Can I use. 각 카드에는 분류·이름·한 줄 설명·도메인·외부 링크 화살표를 표시한다.
- 분류는 일반 텍스트로 표시한다. 이번 단계의 동작은 카드 링크 열기와 키보드 포커스 이동이다.
- 실제 화면은 HTML/CSS/JavaScript로 구현하며 시안 이미지는 실행 화면에 사용하지 않는다.

## 2단계 구현과 확인 기록

실행 파일은 `index.html`, `styles.css`, `app.js`다. 앱은 이 세 파일만으로 실행되며 신규 패키지를 설치하지 않았다.

프로젝트 폴더에서 다음 명령으로 확인할 수 있다.

```sh
python3 -m http.server 4319 --bind 127.0.0.1
```

접속 주소: <http://127.0.0.1:4319/>. 이번 확인에 사용한 로컬 서버는 결과를 볼 수 있도록 실행 상태로 남겼다.

- `node --check app.js` 통과.
- 내장 브라우저 연결을 시도했지만 사용 가능한 브라우저 목록이 비어 있어 로컬 Playwright Chromium으로 대체했다. 기존 개발 환경의 Playwright를 검증 도구로만 사용했다.
- 일반 샌드박스에서 Chromium 실행이 차단되어 승인된 외부 실행으로 검증했다.
- 실제 HTTP 200, 카드 6개, 분류별 2개, 제목과 순서, 표시된 링크 수를 확인했다.
- 1586 × 992 / 1440 × 900 / 768 × 1024 / 390 × 844에서 각각 3 / 3 / 2 / 1열을 확인했고 가로 넘침은 없었다.
- 데스크톱의 마지막 카드 하단은 각각 923.61px / 853.72px로 화면 안에 들어온다. 모바일은 세로로 스크롤해 카드 6개를 본다.
- Tab으로 첫 두 카드에 이동하고 포커스 테두리를 확인했다. MDN 카드를 눌러 해당 HTTPS 주소가 새 탭으로 열리는 것을 확인했다.
- 모션 감소 설정에서는 카드 전환 시간이 0초다. 검사 중 페이지·콘솔 오류와 요청 실패는 없었다.
- 독립 코드 검토에서 중요한 결함을 발견하지 못했다. 신규 파일이 그래프에 아직 반영되지 않아 직접 소스를 읽어 검토했다.
- 링크 추가·태그 필터·즐겨찾기·브라우저 저장 기능과 본편 녹화는 수행하지 않았다.

### 시안과 구현 화면 비교

시안과 [데스크톱 완성 화면](design/first-screen-preview.png)을 `view_image`로 같은 검토 과정에서 직접 비교했다. [모바일 완성 화면](design/first-screen-mobile-preview.png)도 직접 확인했다. 두 미리보기는 2단계 결과를 검토하기 위한 최종 화면 자료다.

| 비교 항목 | 시안과 구현 확인 | 처리 결과 |
| --- | --- | --- |
| 문구 | 제목·설명·컬렉션 이름·링크 수·카드 순서와 카드별 문구 대조 | 기본 화면의 추가·누락 문구 없음. JS 비활성화 안내는 별도 대체 상태다. |
| 배치 | 3열 × 2행, 같은 정렬선과 카드 간격, 카드 하단 링크 영역 | 최초 데스크톱 높이 초과를 발견해 헤더와 카드 내부 간격을 줄였다. 최종 화면은 6개 모두 표시된다. |
| 색상 | 아이보리 배경, 흰 카드, 짙은 글자, 분류별 세 가지 색 | 생성 이미지의 미세한 색상 흔들림을 고정 CSS 색상으로 표현했다. |
| 글자 | 제목과 카드명은 세리프, 설명과 도메인은 sans-serif | 생성 시안에 실제 서체 파일이 없어 시스템 Georgia와 sans-serif로 재현했다. 획의 형태와 일부 줄바꿈은 이미지와 차이가 있다. |
| 카드와 아이콘 | 둥근 16px 모서리, 얇은 경계선, 가는 외부 링크 화살표 | 이미지가 아닌 실제 링크와 SVG로 구현했다. |
| 반응형 | 같은 정보 순서를 유지하며 화면 폭에 맞게 재배치 | 768px에서는 2열, 390px에서는 1열이며 잘림과 가로 넘침 없음. |

시안의 구성·정보·색상 계층을 유지했으며 위에 기록한 시스템 폰트와 반응형 표현 차이가 있다. 사용자 시각 승인과 실제 Blabee를 포함한 녹화 구도 확인은 아직 수행하지 않았다.

## 3단계 구현과 확인 기록

- 제목·HTTP(S) 주소·설명·분류 입력 폼과 링크 추가 동작을 구현했다.
- 빈 제목, 잘못된 주소, HTTP(S)가 아닌 주소는 카드를 추가하지 않고 입력 오류를 표시한다.
- 정상 입력은 새 카드를 목록 맨 앞에 추가하고 링크 수를 갱신한다.
- `node --check app.js`와 로컬 Playwright 검증을 통과했다. 키보드 제출, 오류 상태, 카드 추가, 링크 수, 새로고침 시 초기 상태, 데스크톱·모바일 배치를 확인했다.
- 페이지·콘솔 오류와 요청 실패는 없었고, 독립 QA에서 막는 결함을 발견하지 못했다.
- 태그 필터·즐겨찾기·브라우저 저장은 추가하지 않았다.

## 4A단계 구현 기록

- `Development` 버튼과 해당 분류 카드만 렌더링하는 필터 상태를 추가했다.
- 전체 링크 수 표시는 기존처럼 모든 링크의 수를 유지한다.
- All·Design·Tools 필터는 추가하지 않았다.
- 브라우저 실행과 실제 동작 확인은 수행하지 않았다. 다음 4B단계에서 Development 필터만 확인한다.
