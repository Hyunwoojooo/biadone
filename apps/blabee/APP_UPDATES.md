# Blabee 앱 업데이트 확인

메뉴바 아이콘을 우클릭한 뒤 **업데이트 확인…**을 선택하거나, Blabee 설정의
**앱 업데이트 → 업데이트 확인**을 누른다. 현재 앱의 버전·빌드 번호와 조회 결과를
같은 카드에서 확인할 수 있다. 새 버전이 있으면 **릴리스 페이지 열기**로 이동한다.

조회는 사용자가 버튼을 누를 때만 실행한다. 앱 실행·설정 열기·폴링은 자동 조회를
시작하지 않는다. 업데이트 확인은 앱 다운로드·교체나 Codex 재시작을 실행하지 않는다.

## 배포 정보 계약

- 공개 저장소: [Hyunwoojooo/biadone Releases](https://github.com/Hyunwoojooo/biadone/releases)
- 앱 설정: `Packaging/macos/Info.plist`의 `BlabeeUpdateRepository`.
- 태그: `blabee-vX.Y.Z+build.N`, 예: `blabee-v0.1.0+build.30`.
- `X.Y.Z`는 배포 앱의 `CFBundleShortVersionString`, `N`은 `CFBundleVersion`과
  같아야 한다. 모두 앞자리 0이 없는 정수이고, 빌드는 `1...9999` 범위다.
- GitHub에 **Release로 공개된** 정식 버전만 조회한다. 태그만 만든 상태,
  draft, prerelease, 다른 제품의 태그는 업데이트 후보가 아니다.
- 버전의 세 숫자를 먼저 비교하고 같으면 빌드 번호를 비교한다. 게시 날짜나
  GitHub의 “Latest” 지정은 비교 순서를 바꾸지 않는다.

릴리스를 게시할 때 해당 태그와 일치하는 앱/DMG 및 변경 내용을 첨부한다.
태그의 버전 정보는 게시자가 보장해야 한다. 앱은 설치 파일을 내려받아 그 내부
버전을 검증하지 않는다. 서명·공증·배포 준비는 기존 배포 절차를 따른다.
내부 ad-hoc 설치본을 만들었다는 사실만으로 공개 배포 준비가 끝나지는 않는다.

## 결과와 실패 처리

| 조건 | 표시 |
| --- | --- |
| 공개된 후보가 현재 앱과 같거나 더 오래됨 | 최신 버전입니다 |
| 현재 앱보다 높은 버전 또는 빌드 있음 | 업데이트할 수 있습니다 + 릴리스 페이지 열기 |
| 공개된 Blabee 정식 릴리스 없음 | 등록된 배포 버전이 없습니다 |
| 네트워크·API 한도·권한·응답 형식 문제 | 업데이트를 확인하지 못했습니다 + 재시도 안내 |

GitHub의 공개 [Releases REST API](https://docs.github.com/en/rest/releases/releases)를
로그인·토큰 없이 사용한다. 페이지당 100개, 최대 5페이지를 확인하며 조회 범위가
부족하면 최신이라고 단정하지 않고 확인 실패로 표시한다. `blabee-v`로 시작하지만
계약에 맞지 않는 공개 태그도 배포 정보 문제로 표시한다.

2026-09-11 구현 시점에는 이 저장소의 공개 릴리스가 0개였다. 첫 정식 릴리스를
게시하기 전에는 앱에서 배포 버전 없음으로 표시되는 것이 정상이다.

## 구현·검증 기록 (2026-09-11, 로컬 빌드 30)

- `PetAppUpdates.swift`: 버전 비교, GitHub 조회, 결과·오류 분류.
- `PetAppUpdateView.swift`, `PetView.swift`, `PetPanel.swift`: 상태 카드와 메뉴 진입점.
- `PetViewModel.swift`, `PetApplication.swift`: 명시적 조회, 중복 요청 방지,
  설치 앱의 버전·저장소 연결, 설정 진입 시 로컬 연결 정보 갱신.
- `Packaging/macos/Info.plist`, `scripts/build-macos-app.mjs`: 배포 저장소를 번들에
  포함하고 조립 단계에서 검증.

검증 결과:

- Swift 업데이트·설정·메뉴·상세 미리보기 회귀 테스트 **157개 통과**.
- 앱 조립·무결성 관련 Node 테스트 **34개 통과**.
- 상태 6개 × 폭 2개 × 밝은/어두운 테마, **24개 오프스크린 렌더** 생성.
  업데이트 있음·배포 없음 화면을 직접 확인했다.
- 실제 URLSession 조회에서 공개 저장소의 빈 릴리스 목록을 받아
  **등록된 배포 버전이 없습니다**로 처리했다. 새 릴리스 있음·API 오류·페이지네이션은
  주입한 응답으로 검증했다. 실제 서버의 리다이렉트·대용량 스트림은 재현하지 않았다.
- 독립 코드 리뷰의 설정 새로고침 지적을 수정하고 회귀 테스트를 통과했다.
- Release 빌드, 앱 ad-hoc 서명 검증, 런타임 무결성 검사 통과.
