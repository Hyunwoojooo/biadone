# 연결 상태 화면 개선

- 작성: 2026-09-09 (KST)
- 갱신: 2026-09-10 (KST)
- 범위: 설정 화면의 상태 표시·안내. Codex 실행 방식과 승인 정책은 변경하지 않음
- 배포 상태: 초기 연결 요약은 r21 패키지에 포함. 상태 점 변경은 r22 앱 빌드·검사와 설치 안내창 확인까지 완료했으며, 활성 Codex 사용 때문에 설치본 교체는 보류. 기존 DMG·ZIP은 변경하지 않음

## 문제

테스터 PC에서 Plugin 설치와 앱 서비스 연결은 확인됐지만 작업 폴더 `gannet`은
관찰 범위 밖이었다. 등록 뒤에도 실행 중인 서비스에 적용됐는지는 별도 확인이 필요했다.
기존 화면은 서비스 연결, 선택 사항인 자동 시작 등록, Plugin 설치, Hook 신뢰 미확인을
큰 카드로 나열해 사용자가 무엇을 완료했으며 다음에 무엇을 해야 하는지 알기 어려웠다.
이 사례만으로 Hook 신뢰 오류가 확정된 것은 아니다.

## 새 화면

설정 첫 화면에 연결 요약과 다음 행동 버튼을 표시한다. 그 아래 프로젝트 목록을 배치하고,
설치 진단·서비스 관리·이전 연결 정리는 접어 둔다. 자동 시작 서비스는 선택 사항이다.

| 표시 | 의미와 다음 단계 |
|---|---|
| 서비스 연결 필요 / 연결 확인 필요 | 서비스 관리에서 실행 상태와 오류를 확인한다. |
| Codex 연결 설정 필요 | Plugin 연결을 명시적으로 실행한다. |
| 사용할 프로젝트를 추가하세요 | 실제 Codex 작업 폴더를 추가한다. |
| 프로젝트 설정 적용 필요 | 저장된 목록과 실행 중인 목록이 다르다. 추가뿐 아니라 제거도 재시작 후 적용된다. |
| 설정 준비됨 · 동작 확인 필요 | 서비스·Plugin·프로젝트 적용을 확인했다. 실제 작업 폴더와 `/hooks`, 카드·선택 반환은 따로 확인한다. |
| 선택 카드 수신 확인 | 이 앱에서 해당 프로젝트의 선택 카드를 받았다. 다른 프로젝트나 선택 반환까지 보증하는 표시는 아니다. |

색만으로 상태를 구분하지 않고 상태 점·제목·설명·다음 행동을 함께 제공한다.
앱 실행형 서비스는 명시적인 재시작 버튼으로 설정을 적용한다. macOS 자동 시작 서비스는
‘프로젝트 적용 방법’을 보여 주고, 진행 중인 요청을 먼저 마친 다음 기존 등록 해제·재등록 UI로
적용하도록 안내한다. 자동으로 실행 방식을 바꾸지 않는다.

## 상태 점과 색 기준 (2026-09-10)

연결 요약, 체크 항목, 관찰 프로젝트, 서비스·Plugin 상세 카드에 같은 기준의 상태 점을
사용한다. 접힌 설치·서비스 관리 항목에도 점이 남아 있어 상세를 열기 전 상태를 볼 수 있다.
카드의 배지는 상태 점과 읽을 수 있는 텍스트를 함께 표시한다. 상태 점은 장식 요소로
처리하고, 접근성 읽기에는 텍스트를 사용한다. 요약에는 색의 의미를 설명하는 범례도 표시한다.

| 색 | 의미 | 예 |
|---|---|---|
| 초록 | 그 항목의 확인이 완료됨 | 서비스 연결됨, Plugin 설치 완료, 저장한 프로젝트 적용 확인 |
| 주황 | 설정 또는 사용자 조치가 필요함 | Plugin 미설치, 프로젝트 미등록, 서비스 재시작·macOS 승인 필요 |
| 빨강 | 실제 실패·충돌이 확인됨 | 서비스 통신 오류, Plugin 검사 실패·충돌 |
| 회색 | 미확인·확인 중 또는 선택 기능 미사용 | Hook 신뢰 자동 판정 불가, 카드 수신 확인 전, 자동 시작 꺼짐 |

Plugin 설치 완료는 초록으로 표시하되 Hook 신뢰 안내는 별도의 회색 항목으로 나눈다.
Hook 신뢰를 앱에서 확인할 수 없다는 이유만으로 주황 경고를 표시하지 않는다. 이미 사용자가
신뢰를 승인했거나 카드가 수신됐을 수도 있으므로 ‘신뢰하지 않음’이라고 단정하지 않는다.
실제 카드 수신 전의 전체 요약은 회색을 유지한다. 자동 시작 미등록도 선택 사항이므로 회색이며,
등록됐다는 초록 표시는 서비스 실행·연결 성공까지 의미하지 않는다.

색 매핑은 `PetSettingsStatusTone`, 점·배지·범례는 `PetSettingsStatusIndicator`에서 공유한다.
오류와 조치 필요를 분리하기 위해 체크 항목의 표시 상태에 `failed`를 추가했지만, 연결 요약의
추천 순서·다음 행동·실행 권한 판정은 변경하지 않았다. 재검사나 재시작은 기존 버튼을 통해서만 수행한다.

## 증거 경계

- Plugin 설치·활성 확인을 Hook 신뢰나 전체 연결 완료로 표현하지 않는다.
- 현재 응답하는 서비스의 snapshot만 프로젝트 적용 판단에 사용한다.
- 세션 목록은 저장된 기록일 수 있으므로 현재 Hook 동작의 증거로 사용하지 않는다.
- 선택 카드 수신 기록은 메모리에만 유지한다. 선택 후 카드가 사라져도 수신 확인을 유지하며,
  서비스 연결 실패·앱 실행형 서비스 전환 때 초기화한다. 비활성 프로젝트는 제외한다.
- 선택 결과가 Codex에 반환됐는지, 요청한 작업이 성공했는지는 이 요약에서 자동 판정하지 않는다.
- 화면만으로 현재 사용자 터미널의 작업 폴더를 알 수 없다. 등록 폴더와 하위 경로만
  관찰하며 같은 저장소의 다른 worktree를 자동으로 등록하지 않는다.
- 새 폴링·자동 설치·신뢰 승인·테스트 프롬프트 전송을 추가하지 않는다.

## 상태 점 변경 검증 (2026-09-10)

- Swift Testing 823개 중 821개 + XCTest 5개 통과. 벤치마크·설치된 Codex 실검증 2개는
  비활성 검사로 건너뛰었다. 앱·테스트 타깃 컴파일 완료.
- Plugin 설치와 Hook 미확인, 등록과 실행, 오류와 설정 조치, 서비스 전환·연결 상실을 구분하는
  테스트를 추가했다. 등록 해제가 필요한 `.blocked`는 요약과 상세 모두 주황이며, 실제 서비스
  종료·통신 오류는 빨강이다. 기존 서비스 실행·등록·해제 경로는 변경하지 않았다.
- 라이트·다크 요약 8장과 상태 배지·범례 4장을 offscreen 렌더링했다. 요약과 배지의 상태 점,
  텍스트, 좁은 폭에서 범례의 2열 배치를 확인했다. 설치본의 유리 효과와 실제 클릭·VoiceOver
  동작을 검증한 결과는 아니다.
- 첫 전체 검사에서 새 렌더 테스트의 너비 완전 일치 비교 4건이 부동소수점 오차로 실패했다.
  별도 재현 후 0.01pt 이내 비교로 바꾸고 전체 검사를 다시 통과했다. 화면 너비를 변경하거나
  테스트를 제외하지 않았다.
- 독립 코드 검토에서 확인한 `.blocked` 색상 불일치와 접힌 항목의 접근성 상태 안내 누락을
  수정했고, 재검토에서 미해결 지적은 없었다.
- `git diff --check` 통과. 이번 상태 점 변경은 설치본·DMG·ZIP에 아직 반영하지 않았다.
  후속 [r22 빌드·설치 준비 기록](R22_SETTINGS_STATUS_ACCEPTANCE_KO.md)에 현재 차단 이유와
  안전하게 설치를 마치는 순서를 기록했다.

## 초기 연결 요약 검증과 배포 기록 (2026-09-09)

상태 판정 및 ViewModel 회귀 테스트는 서비스 오류, 미설치, 설정 읽기 실패,
프로젝트 추가·제거, 과거 세션, 카드 선택 후 수신 기록과 연결 실패 시 초기화를 다룬다.
가짜 상태를 주입한 라이트·다크 8개 화면에서 요약·프로젝트 목록의 배치를 확인했다.
macOS 유리 효과와 일부 네이티브 컨트롤은 offscreen 이미지에 완전히 합성되지 않아,
테스트는 유리 효과를 제외한 같은 콘텐츠 트리를 사용한다. 설치본의 최종 외형·실제
버튼 클릭·스크롤·VoiceOver와 Codex 왕복 검증을 대신하지 않는다.

- 전체 Swift Testing 805개 + XCTest 5개 통과.
- Node 계약·패키징·런타임 회귀 테스트 360개 통과.
- 전체 검사 중 발견한 반복 연결 실패 시 불필요한 상태 발행을 수정하고 재통과했다.
- 독립 코드 재검토: 요청 범위의 추가 P1/P2 없음. 실제 UI 조작은 미검증.
- `git diff --check` 통과.

후속 작업으로 build 20 앱을 생성하고 소스·서명·리소스를 검사했다. 기존 설치본을 사용하는
Codex/MCP가 있어 교체·재시작은 보류했다. 실제 화면 제어도 설치 경로 조회 timeout과
번들 ID 중복으로 진행되지 않았다. [r20 준비·검증 기록](R20_SETTINGS_UI_ACCEPTANCE_KO.md)을 참고한다.

이후 초기 연결 요약은 [r21 패키지](INTERNAL_DMG_R21_RELEASE_KO.md)에 포함됐다.
상태 점 변경이 포함된 새 DMG 생성·설치본 교체와 다른 Mac 검증은 별도 작업이다.
실제 폴더 등록 → 서비스 적용 → 카드 수신 → 원래 세션 반환도 화면 표시 검증과 구분한다.
