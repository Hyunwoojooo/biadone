# 연결 상태 화면 개선

- 작성: 2026-09-09 (KST)
- 범위: 설정 화면의 상태 표시·안내. Codex 실행 방식과 승인 정책은 변경하지 않음
- 배포 상태: build 20 앱 생성·검사 완료. 현재 build 18 설치본과 기존 r19 DMG·ZIP에는 미반영

## 문제

테스터 PC에서 Plugin 설치와 앱 서비스 연결은 확인됐지만 작업 폴더 `gannet`은
관찰 범위 밖이었다. 등록 뒤에도 실행 중인 서비스에 적용됐는지는 별도 확인이 필요했다.
기존 화면은 서비스 연결, 선택 사항인 자동 시작 등록, Plugin 설치, Hook 신뢰 미확인을
큰 카드로 나열해 사용자가 무엇을 완료했으며 다음에 무엇을 해야 하는지 알기 어려웠다.
이 사례만으로 Hook 신뢰 오류가 확정된 것은 아니다.

## 새 화면

설정 첫 화면에 연결 요약과 다음 행동 버튼을 표시한다. 그 아래 프로젝트 목록을 배치하고,
설치 진단·서비스 관리·이전 연결 정리는 접어 둔다. 자동 시작 서비스는 선택 사항이다.

| 표시 | 의미와 다음 단계 |
|---|---|
| 서비스 연결 필요 / 연결 확인 필요 | 서비스 관리에서 실행 상태와 오류를 확인한다. |
| Codex 연결 설정 필요 | Plugin 연결을 명시적으로 실행한다. |
| 사용할 프로젝트를 추가하세요 | 실제 Codex 작업 폴더를 추가한다. |
| 프로젝트 설정 적용 필요 | 저장된 목록과 실행 중인 목록이 다르다. 추가뿐 아니라 제거도 재시작 후 적용된다. |
| 설정 준비됨 · 동작 확인 필요 | 서비스·Plugin·프로젝트 적용을 확인했다. 실제 작업 폴더와 `/hooks`, 카드·선택 반환은 따로 확인한다. |
| 선택 카드 수신 확인 | 이 앱에서 해당 프로젝트의 선택 카드를 받았다. 다른 프로젝트나 선택 반환까지 보증하는 표시는 아니다. |

색만으로 상태를 구분하지 않고 아이콘·제목·설명·다음 행동을 함께 제공한다.
앱 실행형 서비스는 명시적인 재시작 버튼으로 설정을 적용한다. macOS 자동 시작 서비스는
‘프로젝트 적용 방법’을 보여 주고, 진행 중인 요청을 먼저 마친 다음 기존 등록 해제·재등록 UI로
적용하도록 안내한다. 자동으로 실행 방식을 바꾸지 않는다.

## 증거 경계

- Plugin 설치·활성 확인을 Hook 신뢰나 전체 연결 완료로 표현하지 않는다.
- 현재 응답하는 서비스의 snapshot만 프로젝트 적용 판단에 사용한다.
- 세션 목록은 저장된 기록일 수 있으므로 현재 Hook 동작의 증거로 사용하지 않는다.
- 선택 카드 수신 기록은 메모리에만 유지한다. 선택 후 카드가 사라져도 수신 확인을 유지하며,
  서비스 연결 실패·앱 실행형 서비스 전환 때 초기화한다. 비활성 프로젝트는 제외한다.
- 선택 결과가 Codex에 반환됐는지, 요청한 작업이 성공했는지는 이 요약에서 자동 판정하지 않는다.
- 화면만으로 현재 사용자 터미널의 작업 폴더를 알 수 없다. 등록 폴더와 하위 경로만
  관찰하며 같은 저장소의 다른 worktree를 자동으로 등록하지 않는다.
- 새 폴링·자동 설치·신뢰 승인·테스트 프롬프트 전송을 추가하지 않는다.

## 검증과 배포

상태 판정 및 ViewModel 회귀 테스트는 서비스 오류, 미설치, 설정 읽기 실패,
프로젝트 추가·제거, 과거 세션, 카드 선택 후 수신 기록과 연결 실패 시 초기화를 다룬다.
가짜 상태를 주입한 라이트·다크 8개 화면에서 요약·프로젝트 목록의 배치를 확인했다.
macOS 유리 효과와 일부 네이티브 컨트롤은 offscreen 이미지에 완전히 합성되지 않아,
테스트는 유리 효과를 제외한 같은 콘텐츠 트리를 사용한다. 설치본의 최종 외형·실제
버튼 클릭·스크롤·VoiceOver와 Codex 왕복 검증을 대신하지 않는다.

- 전체 Swift Testing 805개 + XCTest 5개 통과.
- Node 계약·패키징·런타임 회귀 테스트 360개 통과.
- 전체 검사 중 발견한 반복 연결 실패 시 불필요한 상태 발행을 수정하고 재통과했다.
- 독립 코드 재검토: 요청 범위의 추가 P1/P2 없음. 실제 UI 조작은 미검증.
- `git diff --check` 통과.

후속 작업으로 build 20 앱을 생성하고 소스·서명·리소스를 검사했다. 기존 설치본을 사용하는
Codex/MCP가 있어 교체·재시작은 보류했다. 실제 화면 제어도 설치 경로 조회 timeout과
번들 ID 중복으로 진행되지 않았다. [r20 준비·검증 기록](R20_SETTINGS_UI_ACCEPTANCE_KO.md)을 참고한다.

DMG 생성·설치본 교체와 다른 Mac 검증은 별도 작업이다. 테스터에게는 기존 r19 화면과
새 UI를 구분해서 안내하고, 실제 폴더 등록 → 서비스 적용 → 카드 수신 → 원래 세션 반환을 확인한다.
