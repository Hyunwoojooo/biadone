## 관찰과 한계

테스터는 build 15와 수정된 디스크 래퍼의 `.local/bin/codex` 경로를 확인했다.
기존 대화형 터미널의 로드된 함수는 미확인이다. 별도 비로그인 zsh의 `충돌 없음`은
원래 터미널의 상태를 증명하지 않는다. Computer Use `-10005`도 Blabee 연결 오류가 아니다.
현재 앱은 공식 Codex를 직접 탐색하므로 구형 래퍼와 앱 연결 실패는 별도로 판정한다.

## 1. 구형 연결 정리

설정에서 `구형 연결 검사 → 정리 내용 확인 → 백업 후 비활성화`를 선택한다.
화면을 열기만 해서는 셸 파일을 읽거나 변경하지 않는다.

공유 파일 덮어쓰기 경쟁을 피하기 위해 **.zshrc는 쓰지 않는다**. 정확한 v4 생성 본문·
메타데이터와 조건부 source 블록이 일치할 때만 래퍼를 고유한 백업 이름으로 이동한다.
기존 조건부 참조는 남지만 파일이 없으므로 실행되지 않는다. Codex 바이너리·대화 기록·
구형 runtime 디렉터리·다른 Plugin은 변경하거나 삭제하지 않는다.

- 수정본, v1~v3, 추가 참조, 동적인 ZDOTDIR는 자동 정리하지 않는다.
- HOME/ZDOTDIR 시작 파일과 래퍼 스냅샷을 확인에 묶고, 확인은 실패 시에도 한 번만 소비한다.
- 공통 파일 잠금, descriptor 기반 경로 접근, 덮어쓰기 없는 rename으로 처리한다.
- 링크·위험한 소유권/권한/ACL·크기 초과·읽는 중 변경을 거부한다.
- 충돌 복귀도 새 파일을 덮어쓰지 않는다. 복귀 불가 시 두 파일을 보존하고 수동 확인을 안내한다.
- 성공은 래퍼 한 파일 비활성화만 뜻한다. 열린 터미널의 함수를 바꾸거나 Codex 정상 동작을 보증하지 않는다.

정리 후 같은 셸 설정을 사용하는 새 대화형 터미널에서 `type -a codex`와 `codex --version`을
확인한다. 기존 세션은 강제 종료하지 않는다. 백업을 복원할 때도 이후 사용자 편집을 덮어쓰지 않는다.
GUI가 전체 셸 초기화 체인을 확정할 수 없는 경우 수동 확인으로 남긴다.

## 2. 재검사 피드백

Codex 카드/버튼 근처에 검사 중 상태와 매 명시적 시도의 시작·완료 시각, 경과 시간, 결과를
표시한다. 같은 오류도 새 시도 완료로 구분하며, 이후 상태 조회가 그 기록을 덮어쓰지 않는다.
경로·실제 대상·버전·실패 단계는 같은 검사에서 확인한 것만 기록하고 미확인 값은 추측하지 않는다.
진단 복사는 허용한 필드만 사용하고 홈 경로를 가린다. 원문 stderr·전체 환경·토큰은 제외한다.

재검사는 Plugin 설치, Hook 신뢰 승인, 서비스 활성화가 아니다. 중복 클릭을 큐에 쌓거나
이전 결정/전송을 재실행하지 않는다. 앱의 제한 시간과 외부 화면 도구 오류도 구분한다.

## 검증과 후속 범위

신규 자동 테스트는 임시 HOME·가짜 실행 어댑터를 사용한다. 정확한 v4/수정본/추가 참조/ZDOTDIR,
링크·권한·크기, 확인 후 변경·이동 중 교체·복원 충돌, 반복 요청, .zshrc 바이트 보존을 확인한다.
UI는 승인 전 무변경, 닫은 화면의 늦은 확인 폐기, 검사 진행·반복 완료·상태 조회 후 기록 보존과
진단 비식별화를 검증한다. 테스트 결과는 아래에 별도로 기록한다.

다른 Mac은 새 설치와 구형 업데이트를 나눠 검증한다. 일반 Codex 기본 동작, Hook 실행,
서비스 준비, 카드 표시, 원래 세션 반환, 중복 실행 없음과 재시작 후 유지가 각각 필요하다.
수정된 테스터 래퍼는 자동 정리 성공 대상으로 간주하지 않는다.

최초 소스 작업에서는 탐색 우선순위 변경·실행 파일 선택 UI·지원 버전 확대·실제 설치본 교체·DMG·커밋·푸시가 범위 밖이었다.
