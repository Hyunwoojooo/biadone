# Codex 제안의 구분과 언어

2026-09-23. 적용 범위: Codex Plugin의 제안 생성 지침과 Blabee 표시 구분.

## 제품 정책

- 현재 사용자 작업을 이어가는 선택은 **현재 작업의 다음 선택**으로 표시한다.
- 내부 자동 추천을 포함한 유용한 새 아이디어도 허용하고 **새로운 제안**으로 구분한다.
- 새로운 제안은 서로 다른 실제 유용한 다음 항목이 둘 이상일 때만 제출한다. 0~1개를 채우려고 선택지를 발명하지 않는다.
- 기존 `action_only`, `smart`, `always` 모드의 현재 작업 후속 규칙을 유지한다. 새로운 제안에는 위의 두 개 이상 조건이 우선한다.
- 내부 하위 에이전트 보고나 백그라운드 작업 진행 상태를 그대로 카드로 옮기지 않는다. 네이티브 권한 승인 이벤트는 기존 승인 경로를 유지한다.

## 표시 구분과 전달 계약

MCP `emit_decision`의 최상위 wrapper에 선택 필드 `suggestion_kind`를 추가한다.

| 값 | 의미 |
|---|---|
| `current_task` | 현재 사용자 작업의 후속 선택 |
| `new_suggestion` | 새로운 작업이나 아이디어 제안 |
| 필드 없음 | 이전 클라이언트와의 호환성을 위한 분류 미상 |

현재 MCP 도구 스키마가 지원하면 생성기는 두 종류를 구분해 제출한다.
이전 스키마에는 필드를 넣지 않는다. 필드가 없는 기존 요청은 **다음 선택**으로
표시하고 현재 작업이나 새로운 제안으로 추측해서 분류하지 않는다.
새 필드를 읽는 Coordinator·MCP·Pet은 같은 설치본으로 함께 갱신한다.
이 값은 **표시용 자기 신고 정보**다.
사람이 입력했다는 증명, 자동 생성 여부의 신뢰할 수 있는 판정, 실행 승인으로
사용하지 않는다. 영어 여부로 종류나 출처를 추정하지 않는다.

`suggestion_kind`를 동결된 v1 `proposal`이나 packet 안에 추가하지 않는다.
기존 `schema_version: 1.0`, `interaction_kind: blabee_decision`, 정확한
project/session/turn/prompt/episode/correlation 바인딩과 선택 검증을 유지한다.

새로운 제안도 원래 생성 세션의 정확한 바인딩에 속한다. 종료된 백그라운드
생성 세션에서 나중에 선택을 실행할 수 있다는 보장은 없다. 생성 세션이
사용 불가능하다고 다른 활성 세션으로 자동 전달하거나 임의로 재생하지 않는다.
정확한 세션에서 실행할 수 없는 경우 기존 검증·만료 처리를 따른다.

## 카드 언어

두 종류 모두 다음 순서로 언어를 정한다.

1. 사용자가 명시한 응답 언어.
2. 명시한 언어가 없으면 실제 사용자 대화의 언어.
3. 둘 다 알 수 없으면 `Locale.preferredLanguages`에서 첫 유효 language tag.
4. 시스템 언어도 없거나 유효하지 않으면 `en`.

서버가 세 번째와 네 번째 단계의 fallback 값을 계산해 Hook과 MCP 도구 설명에
넣는다. `BlabeeSuggestionLanguage.fallbackLanguageTag(preferredLanguages:)`는
입력받은 언어 배열만 사용하는 순수 함수다. 지침 생성 함수에도 배열을 주입할 수
있고, 제품 호출의 기본값은 `Locale.preferredLanguages`다. Hook 문구의 크기를
제한하기 위해 UTF-8 기준 128바이트를 넘는 후보는 건너뛴다.

내부 자동 추천을 생성하라는 영어 지시문 자체는 사용자가 응답 언어를 지정한
것이나 실제 대화 언어로 취급하지 않는다. 그 지시문만 언어 단서로 주어졌다면
시스템 언어 fallback을 사용한다.

언어 규칙은 `task_goal`, `outcome.summary`, `next_actions`의 제목·목표·조건·완료
기준, `reported_side_effects`의 설명에 모두 적용한다. 내부 프롬프트·도구 설명·예시의
영어 때문에 언어를 바꾸지 않는다. 코드·경로·식별자·제품명과 사용자가 외국어로
요청한 산출물은 원문을 보존하고 주변 카드 설명에만 카드 언어를 적용한다.

## 구현과 적용

`BlabeeSuggestionContext`의 공통 문구를 `SessionStart`, `UserPromptSubmit`,
MCP `emit_decision` 설명에서 공유한다. 번들 `blabee-decision/SKILL.md`도 같은
정책을 사용하며 스킬 변경에 맞춰 `DoctorApplication.skillSHA256`을 갱신한다.
미배포 Plugin 버전은 `0.1.3`을 유지해 기존 `0.1.2` 설치가 업데이트 대상으로
인식되게 한다.

내부 자동 추천을 수신 단계에서 차단하는 것은 이번 제품 정책의 목표가 아니다.
`QueuedPromptEnvelope.Classification.human`은 기존 Blabee 전달 접두어가 없다는
호환성 분류이며 사람이 직접 입력했다는 출처 증명이 아니다. 언어·transcript·
Codex DB 행의 존재 여부로 새로운 출처 판정을 만들지 않는다.

이 언어 처리는 **모델 생성 지침과 시스템 언어 fallback 제공**이다. 서버가
제안을 자동 번역하거나 모든 문장의 언어를 검증·거절하는 기능은 아니다.

## 검증 범위와 실사용 확인

자동 검사는 wrapper 분류와 기존 v1 계약의 분리, 분류 미상의 호환 처리, 정확한
세션 유지, 공통 정책 주입, 결정적인 시스템 언어 fallback, 번들 스킬과 doctor
해시 일치를 확인한다. 모델의 실제 언어 준수나 종료된 생성 세션의 실행 가능성은
이 검사만으로 증명되지 않는다.

새 앱과 Plugin을 빌드·설치한 뒤 아래 항목을 별도로 확인한다. 실행 중인 이전
앱이나 이미 로드한 Plugin 캐시에 소스 변경이 자동 적용되지는 않는다.

| 실사용 시나리오 | 확인할 결과 |
|---|---|
| 일반 작업의 후속 선택 | 현재 작업 후속으로 표시되고 원래 대화로 전달된다. |
| 내부 자동 추천의 유용한 새 아이디어 둘 이상 | 새로운 제안으로 표시되고 사용자 언어를 따른다. |
| 유용한 새 아이디어가 0~1개 | 개수를 채운 제안을 제출하지 않는다. |
| 한국어 대화 | 요약·제목·상세 문구가 한국어다. |
| 영어 응답을 명시한 작업 | 영어 카드가 생성된다. |
| 대화 언어를 알 수 없는 자동 추천 | Hook 또는 MCP에 제공된 시스템 언어 fallback을 따른다. |
| 한국어 대화에서 영어 홍보문 요청 | 영어 산출물을 보존하고 카드 설명은 한국어다. |
| 분류 없는 이전 클라이언트 요청 | 임의로 종류를 단정하지 않는다. |
| 생성 세션 종료 후 새 제안 선택 | 다른 세션으로 자동 우회하거나 재생하지 않는다. |
| 하위 에이전트의 네이티브 승인 | 기존 승인 경로가 정상 동작한다. |

원본 보고서의 7건은 보고서에 기록된 관측이다. 해당 원본 실행과 모델 응답을
재현한 검증은 별도로 남아 있다.
