    구조를 설명하는 12개의 관점

    다이어그램이 무엇을 보여 주는지, 왜 그렇게 나뉘었는지, 어떤 위험과 품질 목표가 남아 있는지를 연결합니다.

    원문 Markdown ↗
    01소개와 목표⌄

    Blabee는 결정 경계에서 근거와 연결된 선택을 보여 주고, 사용자가 고른 작업을 같은 Codex 세션의 새 사용자 턴으로 이어 주는 로컬 개발 보조 시스템입니다.

    02아키텍처 제약⌄

    macOS, Codex Plugin, 제한된 Hook fail-open, 로컬 SQLite·Keychain, 명시적 관리형 경로라는 제약 아래 비밀과 원문 token을 확산하지 않습니다.

    03컨텍스트와 범위⌄

    제품 경계에는 Plugin, Coordinator, Pet, 인증된 원장이 있고 Codex와 macOS Keychain은 외부 actor·시스템으로 상호작용합니다. Blabee cloud inference backend는 없습니다.

    04해결 전략⌄

    Plugin-first ingress, 단일 Coordinator authority, 표시와 권한의 분리, 인증된 원장, 정확히 한 번의 연속 진행, 경로별 실패 정책을 조합합니다.

    05빌딩 블록 뷰⌄

    Plugin, Coordinator, Pet, Decision Journal, Keychain, 선택형 Managed Codex bridge의 실행 책임과 Coordinator 내부 계층을 C4로 나눕니다. Plugin 설치·복구는 사용자 확인, 작업 기한과 신뢰 재검증을 갖는 별도 경계입니다.

    06런타임 뷰⌄

    결정 연속 진행, Hook 권한 요청, 관리형 승인, 결정 경계 lifecycle에서 요청·선택·receipt·작업 결과를 분리합니다.

    07배포 뷰⌄

    한 사용자 Mac의 Plugin, UDS, Coordinator service, SQLite, Keychain과 명시적 blabee-codex child tree를 배치합니다. 내부 DMG는 빌드 번호를 앱과 배포 파일명에 맞추며, r8의 기존 단일 개발자 Mac 설치·서비스 복구 기록과 추가 설치·공개 배포 자격을 구분합니다.

    08횡단 관심사⌄

    runtime identity, exactly-once, monotonic time, 개인정보, 관측성과 증거 성숙도가 모든 흐름을 가로지릅니다.

    09아키텍처 결정⌄

    현재 소스에서 역추적한 선택은 회고형 ADR로 기록하고, 알 수 없는 최초 결정일이나 검토하지 않은 대안을 만들어내지 않습니다.

    10품질 요구사항⌄

    네이티브 지속성, 안전한 선택, 중복 방지, 영속 무결성, 프라이버시, 연속 진행을 시나리오와 증거 수준으로 연결합니다.

    11위험과 기술 부채⌄

    설치본 App Server 자격, Codex 버전 결합, 배포 신뢰 사슬, Hook 관측 한계와 same-UID 잔여 위험이 남아 있습니다. 문서는 확인한 커밋에 고정되며, 이후 커밋이나 작업 트리 변경은 재검증이 필요합니다.

    12용어집⌄

    Decision boundary, Packet, Episode, queued_next_turn, Runtime identity, Delivery ack, Freshness anchor와 As-Is/GATE의 정확한 뜻을 고정합니다.

    로컬 socket 권한만으로 신뢰를 완료하지 않고 packaged runtime identity와 operation allowlist를 함께 검증합니다.

    ADR-0004외부 키 인증 SQLite journal과 Keychain freshness를 사용⌄

    MAC chain, 외부 키, Keychain high-water를 결합해 손상과 과거 snapshot 복원의 모호성을 실패 폐쇄합니다.

    Accepted · Retrospective · Persistence

    원문 열기 ↗

    ADR-0005Native Codex Preservation과 비대칭 실패 정책을 불변 조건으로 둠⌄

    일반 Hook 보조 기능은 제한적으로 fail-open하지만 MCP·영속 mutation·관리형 실행의 신뢰 경계는 불확실성을 성공으로 만들지 않습니다.

    Accepted · Retrospective · Failure policy

    원문 열기 ↗

    ADR-0006exact identity 전역 FIFO와 queued-next-turn 전달을 사용⌄

    Pet의 선두 요청과 사용자의 exact 선택을 묶고, 같은 Codex session의 queue --message에 참조 envelope를 전달합니다. 정확한 UserPromptSubmit 재진입에서 journal의 sealed action을 한 번 claim해 Hook context로 제공합니다.

    Accepted · Retrospective · queued_next_turn

    원문 열기 ↗

    ADR-0007App Server 권한 중계를 명시적 opt-in 관리형 실험으로 격리⌄

    고권한 App Server 승인 중계는 사용자가 시작한 blabee-codex에만 열고 일반 codex 경로와 격리합니다. 종료 시 해당 App Server·TUI child를 제한된 시간 안에 정리합니다. 일반 Plugin CLI 호환성과 관리형 실행 자격은 별개이며, 설치본 승인 live 왕복은 GATE입니다.

    Accepted · Retrospective · Managed approval

    원문 열기 ↗

    ADR-0008Coordinator, Plugin, 계약, 서비스 정의를 macOS 앱에 함께 패키징⌄

    실행 파일과 frozen contracts, Plugin, 서비스 계약을 한 bundle에 묶고 앱·DMG의 빌드 번호를 일치시킵니다. 내부 arm64·ad-hoc r8의 한 개발자 Mac 설치·서비스 복구는 기존 LIVE 기록이며 이번 문서 갱신에서 재실행하지 않았습니다. 깨끗한 다른 Mac, Hook·Pet 왕복, Developer ID·공증은 GATE입니다.

    Accepted · Retrospective · Packaging
