# Blabee 사용 기록

추가 확장: [제안 반응 및 사용자 피드백](PRODUCT_FEEDBACK.md). 자동 수집에 카드 노출·반응과
Codex 검사 환경이 추가되어 현재 동의 키는 `blabee.usageAnalytics.enabled.v3`이다.
이전 v2 설정은 승계하지 않는다. 아래 세 가지 사용 횟수 정의는 그대로 유지한다.
직접 제출하는 대화와 의견은 자동 사용 통계와 분리된 공유 화면과 API를 사용한다.

2026-09-17 추가 요청으로 같은 선택적 사용 통계에 [제품 개선 지표](PRODUCT_METRICS.md)를
추가했다. 아래 사용 횟수·활동일의 정의와 기존 RPC는 유지한다. 설정 진행 단계,
기능 시도/결과·속도 구간, 버튼/단축키, 앱·OS 버전·표시 언어, 업데이트 결과는
별도 제품 지표 RPC와 집계에 저장하며 기존 사용 횟수를 증가시키지 않는다.
수집 범위가 늘어난 버전에서는 `blabee.usageAnalytics.enabled.v2` 동의를 새로 받으며,
이전 버전에서 전송을 켰어도 새 범위는 자동으로 켜지지 않는다.

## 범위와 측정 기준

2026-09-17 사용자 선택: **사용 횟수, 활동일, 마지막 사용일**. 실행 시간이나 활동 시간 추정은 수집하지 않는다.

사용 횟수 1회는 사용자가 다음 행동을 수행하고, 앱이 Coordinator의 정상 접수 응답을 검증한 경우다.

| 이벤트 | 의미 |
| --- | --- |
| `choice_accepted` | 선택지 실행 또는 기존 일시정지 선택이 접수됨 |
| `approval_resolved` | 기본/관리형 권한 요청에 대한 승인 또는 거절이 접수됨 |
| `suggestion_dismissed` | 사용자가 제안 건너뛰기를 수행했고 그 대상의 처리 응답을 확인함 |

AI 작업이나 명령의 실행 완료를 뜻하지 않는다. 앱 실행, 창 표시, 카드 읽기, 자동 폴링, 로그인 및 토큰 갱신은 이 횟수에 포함하지 않는다. 버튼과 전역 단축키는 같은 처리 지점에서 한 번만 기록한다. 접수 실패, 오래된 카드의 클릭, 취소된 확인 창은 기록하지 않는다.

측정은 업데이트한 앱에서 로그인하고 사용 통계 전송을 켠 뒤 시작한다. 이전 사용을 소급 생성하지 않는다. 기록이 없다는 사실로 과거에 사용한 적이 없거나 앱을 삭제했다고 판단하지 않는다. 조회 결과는 항상 **관측된 사용**이다.

## 사용자가 선택하는 전송

- 설정 → 일반 → 사용 통계 → **사용 통계 보내기**. 초기값은 꺼짐이며 이 Mac에 적용한다.
- 아래 세 종류의 사용 횟수 이벤트는 로그인 계정의 사용자 ID, 고정된 행동 종류, 발생 시각을 사용한다. 네트워크 재전송 식별을 위한 무작위 이벤트 ID도 포함한다. 추가 제품 지표의 필드는 연결 문서에서 별도로 정의한다.
- 이메일은 Auth 계정 정보에만 두고 사용 이벤트에 복제하지 않는다. 운영자가 조회할 때 사용자 ID로 연결한다.
- 대화, 코드, 명령, 경로, 선택지 원문, 프로젝트 이름, Codex 세션 ID, 인증 토큰을 사용 기록에 저장하지 않는다.
- 기능 요청을 시작한 계정과 접수 응답을 받은 계정이 다르면 기록하지 않는다.
- 기능 요청을 시작할 때의 전송 동의도 확인한다. 응답 대기 중 전송을 껐다 켜거나 같은 계정으로 로그아웃·재로그인해도 이전 행동을 새 동의에 포함하지 않는다.
- 전송을 끄거나 로그아웃하면 아직 보내지 않은 기록을 폐기하고 대기 파일 삭제를 시도한다. 이미 서버에 접수된 통계는 되돌리지 않는다.
- 대기열을 폐기할 때 독립된 세대 값을 먼저 갱신한다. 파일 삭제가 실패하더라도 다음 실행에서 이전 세대의 기록을 다시 보내지 않는다.
- 날짜별 통계는 계정 삭제까지 유지하며 `auth.users` 삭제 시 함께 삭제된다. 서비스 공개 전 개인정보 안내에 이 범위와 목적, 보관 기준을 반영한다.

## 앱과 서버

앱의 기능 접수 확인 → 별도 전송 대기열 → 로그인 토큰으로 Supabase RPC 호출 → 중복 검사 → UTC 날짜별 집계 순서다. 사용 기록 전송이 실패해도 Blabee 기능은 실패시키지 않는다.

앱 대기열은 Coordinator SQLite와 분리한다. 최대 256건, 최대 7일의 기록만 보관하며 인증 토큰은 포함하지 않는다. 재시도는 같은 이벤트 ID를 사용하고, 다른 계정의 토큰으로 대기 기록을 보내지 않는다. 네트워크/인증 복구 뒤 재전송하며 종료 시 미완료 작업을 정리한다.

RPC: `public.record_blabee_usage(p_event_id uuid, p_event_kind text, p_occurred_at timestamptz)`.

- `user_id`는 요청 본문에서 받지 않고 서버의 `auth.uid()`로 결정한다.
- 발생 시각은 최근 7일 이내와 서버 시각보다 최대 5분 앞선 범위만 허용한다. 단말 시계가 크게 잘못되면 기록이 누락될 수 있다.
- `blabee_analytics.event_receipts`의 사용자/이벤트 ID 고유 키로 재전송을 구분한다.
- `blabee_analytics.daily_activity`에 날짜/행동별 횟수와 최초/최종 시각을 누적한다.
- 두 테이블은 비공개 스키마에 두고 클라이언트의 직접 읽기/쓰기를 막는다. 인증한 사용자는 제한된 기록 RPC만 호출할 수 있다.
- 중복 검사와 날짜별 집계는 같은 트랜잭션이다. 중복 응답도 앱에서는 전송 완료로 취급한다.
- 중복 판정용 영수증은 8일이 지난 뒤 운영용 정리 쿼리로 제거할 수 있다. 날짜별 집계는 유지된다.

## 운영자가 확인하는 지표

`supabase/usage-reports.sql`은 관리자 SQL Editor용이다. 사용자용 공개 API나 공개 뷰가 아니다.

| 지표 | 해석 |
| --- | --- |
| 첫 관측 사용일 | 통계 전송이 시작된 이후 처음으로 기록한 행동 시각 |
| 마지막 관측 사용일 | 가장 최근 기록한 행동 시각 |
| 누적 사용 횟수 | 정상 접수된 세 종류 행동의 합 |
| 활동일 수 | 최소 한 번 기록한 서로 다른 UTC 날짜의 수 |
| 최근 7일/30일 활성 사용자 | 해당 기간에 기록이 있는 서로 다른 계정의 수 |
| 마지막 사용 후 경과일 | 마지막 관측일로부터 지난 기간. 사용 중단 확정이 아님 |
| D7 재방문 | 첫 관측일로부터 7일 뒤 UTC 날짜에 다시 활동한 비율. 관측 기간이 충분한 집단만 분모에 포함 |

계정 생성일과 첫 관측 사용일은 다르다. 가입 후 미사용과 수집 비동의를 통계만으로 구분할 수 없다. 시간대가 다른 사용자를 비교할 때 현재 일별 기준이 UTC임을 명시한다.

이 수치는 제품 개선용이다. 응답 유실, 오프라인 대기열 한도, 앱 종료, 비동의, 잘못된 단말 시계 등으로 누락될 수 있으며 과금이나 정확한 전체 사용자 수의 근거로 사용하지 않는다. 탈퇴 시 기록도 삭제되므로 과거 집계가 바뀔 수 있다.

중복 판정용 영수증 정리 작업은 자동 예약하지 않았다. 필요할 때 `supabase/usage-reports.sql`의 관리자 정리 쿼리를 실행하고, 운영 주기에 맞춰 별도 예약한다.
