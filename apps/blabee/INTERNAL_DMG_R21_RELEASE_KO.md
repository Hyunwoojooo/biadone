## r21에서 바뀐 점

- 설정 첫 화면에 연결 요약과 다음 행동을 표시하고, 바로 아래에서 관찰 프로젝트를 확인한다.
  Codex 설치·진단과 서비스 관리 등 세부 설정은 펼쳐서 사용한다.
- **Blabee 서비스**, **Codex Plugin**, **관찰 프로젝트**, **실제 선택 카드** 상태를 구분한다.
  **설정 준비됨 · 동작 확인 필요**는 실제 Hook·선택 반환까지 통과했다는 뜻이 아니다.
  **선택 카드 수신 확인**은 표시된 프로젝트의 수신 증거이며 다른 프로젝트나 작업 완료를
  보증하지 않는다. 프로젝트 추가·제거 뒤 현재 서비스에 미적용이면 재시작을 안내한다.
- 일반 명령 권한 카드에 **1 이번만 승인 · 2 거절 · 3 Codex에서 직접 선택**을 항상 표시한다.
  승인 불가 요청에서는 1번이 비활성이고 이유가 보인다. 번호가 거절 등 다른 선택으로
  바뀌지 않으며, 전달 중에는 중복 선택을 차단한다.
- 실행 중인 공식 Codex의 서명 정보를 조회할 때 필요한 Team ID를 읽도록 수정했다.
  승인 자격은 공식 Codex `0.153.4` arm64의 고정된 코드 서명과 현재 Hook 호출 관계가
  검증된 요청에 한정된다. 버전 문자열만으로 승인 자격을 부여하지 않는다.

일반 `codex` 실행 방식·공식 설치본·셸 설정·기본 resume은 변경하지 않는다.
Codex를 번들에 넣거나 구버전으로 바꾸지 않는다. 앱 실행·설치·Plugin 설치·Hook 신뢰는
서로 다른 단계이며 Hook 신뢰는 새 Codex 세션의 `/hooks`에서 사용자가 직접 검토한다.

## 알려진 제한

- Apple Silicon 내부 테스트 후보다. 선언된 최소 macOS가 모든 해당 OS의 실기기 통과를
  뜻하지 않는다. Intel·다른 Mac/OS·장시간 안정성은 별도 확인이 필요하다.
- Apple 공증 전이다. macOS/조직 정책으로 실행이 차단되면 우회하지 않는다. 전체
  Gatekeeper 해제, quarantine 제거, 임의 재서명, Codex/host 개별 교체는 하지 않는다.
- 업데이트 전 연결된 Codex 작업을 안전하게 마치고 해당 Codex를 정상 종료한 다음,
  메뉴바 우클릭 → **Blabee 종료**를 선택한다. Pet 종료만으로 Codex의 MCP가 종료되지는
  않는다. 설치 안내에서 관련 프로세스가 실행 중이라고 하면 **다시 확인**하고, 계속
  차단되면 상태를 보고한다. 프로세스 일괄 강제 종료나 실행 중 앱 덮어쓰기는 하지 않는다.
- macOS 자동 시작 서비스의 서명 문제는 별개로 남아 있다. 내부 테스트는 사용자가 직접
  켜는 **앱 실행형 서비스**를 사용하며, 자동 시작 서비스 미등록 자체는 오류가 아니다.
- 첫 Keychain 승인 지연·반복 암호 요청·장시간 메모리 증가는 별도로 관찰한다.
  예상하지 못한 요청이나 반복 오류가 있으면 중단한다.
- 수정본/불명확한 구형 셸 래퍼는 자동 정리하지 않는다. 설정 삭제나 symlink 교체로
  우회하지 말고 상태를 보고한다.
- 세 권한 선택지가 보인다는 사실은 1번 승인 자격이나 실제 버튼 왕복을 보증하지 않는다.
  미검증 요청에서는 비활성 이유를 확인하고 **Codex에서 직접 선택**을 사용할 수 있다.
  같은 명령을 다시 요청하면 새 결정이 필요한지, 거절·직접 선택이 원래 Codex 흐름으로
  이어지는지는 별도 테스터 확인 항목이다. 카드 번호 표시와 숫자 키 입력 지원도 구분한다.
