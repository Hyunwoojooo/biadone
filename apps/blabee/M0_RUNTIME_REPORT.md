# M0 코디네이터 런타임 비교 보고서

상태: **증거 게이트 유지 — 운영 런타임 미확정**
측정 시각: 2026-08-20 23:52 KST (`2026-08-20T14:52:58.119Z`)

## 결론

세 후보 모두 동일한 NDJSON `health` 계약을 통과했다. 이 마이크로벤치에서는 C가 시작 지연·실행 파일 크기·peak RSS 모두 가장 작았고, Swift가 그다음, Node가 가장 컸다. 하지만 실제 코디네이터에 필요한 이벤트 저널, 재시작 복구, 진단, 서명·공증 및 업데이트는 아직 측정하지 않았으므로 이 결과만으로 운영 언어를 확정하지 않는다.

- 계약 탐색과 빠른 변경에는 현재처럼 Node ESM을 사용할 수 있다.
- 공개 macOS 패키징의 다음 검증 후보는 Swift 헬퍼로 둔다.
- C는 성능 기준선으로 유지하지만, 전체 계약 구현의 안전성과 유지보수 비용을 검증하기 전에는 운영 후보로 선택하지 않는다.

## 동일 계약

각 프로세스는 stdin에서 newline-delimited JSON 요청 한 줄을 받고 stdout에 응답 한 줄을 보낸다.

```json
{"method":"health"}
```

후보별 `runtime` 값만 다르고 나머지 성공 계약은 같다.

```json
{"ok":true,"runtime":"node|swift|c","protocol_version":1}
```

## 재현 명령

```bash
node --test spikes/m0/tests/runtime-benchmark.test.mjs
node spikes/m0/scripts/benchmark-runtimes.mjs --iterations 30
```

벤치마크 명령은 `blabee.m0.runtime-benchmark.v1` 스키마의 JSON 문서를 stdout에 출력한다. `--skip-rss`로 RSS 표본을 생략할 수 있으며, `BLABEE_SWIFTC`와 `BLABEE_CC`로 컴파일러 실행 파일을 바꿀 수 있다.

Swift와 C는 매 실행마다 운영체제 임시 디렉터리에 컴파일하고 종료 시 해당 디렉터리를 제거한다. 소스 트리에는 빌드 산출물을 남기지 않는다.

## 실제 측정값

| 후보 | p50 | p95 | 최댓값 | 배포 크기 측정 기준 | peak RSS |
|---|---:|---:|---:|---:|---:|
| Node ESM | 19.734 ms | 21.215 ms | 21.289 ms | 소스 591 B, 외부 Node 런타임 별도 | 43,122,688 B (41.13 MiB) |
| Swift 네이티브 | 2.546 ms | 9.508 ms | 308.236 ms | `swiftc -O` 실행 파일 54,712 B | 6,111,232 B (5.83 MiB) |
| C 시스템 바이너리 | 1.091 ms | 1.383 ms | 160.831 ms | `clang -O2` 실행 파일 33,912 B | 1,409,024 B (1.34 MiB) |

모든 후보는 30개 protocol 표본을 통과했다. Swift와 C의 최댓값에는 각각 한 번의 큰 이상치가 있었으므로 평균보다 p50과 p95를 우선 비교해야 한다. Node의 591 B는 Node 런타임을 포함하지 않은 소스 크기라서 Swift/C 실행 파일 크기와 직접 같은 의미로 비교할 수 없다.

## 해석

| 축 | Node ESM | Swift 네이티브 | C 시스템 바이너리 |
|---|---|---|---|
| 현재 강점 | 계약 변경과 디버깅이 빠름 | macOS 앱과 언어·도구 체인을 공유하면서 네이티브 수치가 양호함 | 가장 낮은 지연, 크기, RSS |
| 현재 약점 | 외부 런타임 배포 크기와 메모리가 큼 | 간헐적 시작 이상치와 전체 기능 구현 비용 미측정 | JSON/상태 관리 안전성과 유지보수 부담 미측정 |
| 서명·공증 | Node 포함 방식이 먼저 정해져야 함 | 네이티브 Mach-O 후보이나 실제 검증 전 | 네이티브 Mach-O 후보이나 실제 검증 전 |
| 이번 단계 판단 | 실험용 유지 | 다음 패키징 검증 후보 | 성능 기준선 유지 |

## 아직 운영 선택을 막는 증거

다음 항목을 같은 기능 범위로 구현해 측정하기 전까지 T-005의 운영 런타임 선택은 완료 처리하지 않는다.

1. 이벤트 저널을 가진 최소 코디네이터의 강제 종료 및 재시작 복구
2. 유휴 상태와 지속 부하에서의 메모리 및 IPC 지연
3. Developer ID 서명, 공증, DMG 포함 크기와 업데이트 절차
4. 로그·진단·크래시 조사와 전체 계약 변경 비용
5. Node를 배포할 경우 런타임 번들 방식과 실제 번들 크기

따라서 현재 권장은 **Node로 계약 스파이크를 계속하고, Swift로 다음 운영 패키징 슬라이스를 만들되 최종 선택은 보류**하는 것이다.

## 검증 결과

- protocol/measurement schema 테스트: 통과
- Swift/C 컴파일러 누락 시 `compiler_not_found` 건너뛰기: 통과
- Node/Swift/C 각 30회 health 왕복: 통과
- 임시 빌드 제거: 통과
- 제한된 샌드박스에서 peak RSS를 측정할 수 없을 때 후보 전체를 실패시키지 않고 `unsupported`로 기록: 확인
- 권한이 있는 로컬 실행에서 세 후보 peak RSS 측정: 통과
