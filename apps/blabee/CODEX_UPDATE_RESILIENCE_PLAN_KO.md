# Codex 업데이트 장애 대응 계획

- 작성일: 2026-09-06
- 범위: Blabee 내부의 네이티브 Codex 연결·실행 전 검사·실패 처리와 호환성 검증 자동화
- 상태: 소스 구현 완료, Swift 회귀 및 공식 Codex 0.153.4 런타임 자격 검사 통과,
  Plugin CLI 운영 allowlist 반영·제품 왕복 검증 중, CI 활성화 대기

## 확인한 문제

1. 지원하지 않는 버전, 서명 실패, 실행 실패가 같은 연결 불가 안내로 합쳐진다.
2. Plugin 설치 검사와 다음 작업을 전달하는 `codex queue`가 서로 다른 검증을 사용한다.
3. 차단된 실행 파일을 다시 시도하지 않도록 하는 공통 기록이 없다.
4. 새 버전의 패키지·CLI 계약을 검증하는 반복 가능한 자동화와 증거가 부족하다.

macOS의 최초 공증 조회 실패와 실행 차단은 별도 운영 장애였다. 2026-09-07 공식
0.153.4 전체 재설치 뒤 서명·공증뿐 아니라 실제 CLI와 TUI 시작까지 확인했다.

## 구현 순서와 완료 기준

1. 실패 코드를 보존하고 한국어 안내에서 미설치, 호환성 미검증, 서명,
   공증 확인, 실행 종료/실패, 시간 초과를 구분한다.
2. Plugin과 queue가 공통 실행 전 검사, 기능별 버전 정책, 실행 직전 파일
   재검증을 사용한다. 실패하면 queue 명령을 보내지 않는다.
3. 실행 파일 identity에 결합된 제한된 실패 기록을 프로세스 간 공유한다.
   같은 파일은 명시적 재검사 또는 파일 변경 전까지 재실행하지 않는다.
   기록은 실행 허가나 작업 성공의 증거로 사용하지 않는다.
4. 격리된 런타임의 패키지, 서명·공증, 버전, Plugin/queue 계약을 검사하고
   기계 판독 가능한 호환성 증거를 생성한다. 성공하지 않은 기능은 미검증으로
   남긴다. 자동 검사 결과만으로 운영 버전 목록을 무조건 확대하지 않는다.

## 보존할 경계

- 일반 `codex`, 셸 설정, PATH, resume 및 사용자 세션을 변경하지 않는다.
- Codex 원본 복사·재서명·quarantine 삭제·Gatekeeper 우회는 하지 않는다.
- 전달이 불확실한 명령을 자동 재전송하지 않는다.
- 다른 프로젝트와 기존 작업 트리를 보존한다. 커밋·푸시·설치본 교체는 별도다.
- 실제 macOS 실행 차단이 남아 있으면 새 Codex 버전의 실사용 호환성은
  완료로 보고하지 않는다. 이 Mac의 보안 상태 복구와 제품 회귀 테스트를 구분한다.

## 검증

공통 검사, 파일 교체, 프로세스 재시작, 동시 접근, 명시적 재검사, 오류 보존,
queue 무전송을 격리 테스트로 확인한다. Node/Swift 회귀와 독립 코드 검토를
수행하고, 실제 런타임·Hook·Pet 왕복의 확인 여부를 각각 기록한다.

## 2026-09-06 구현·검증 결과

- Plugin의 모든 조회·설치·제거와 queue 전송을 공통 native gate에 연결했다.
  source alias별 신뢰를 유지하며 깨진 링크·디렉터리는 안전한 다음 후보를 가리지 않는다.
- 실제 POSIX 종료 신호와 일반 종료 코드를 분리했다. 부정확한 출력, 미검증 버전,
  공증·서명 문제, 저장소 오류, 정상 검사 경합을 각각 보존한다.
- 검사 대기 시간을 전체 실행 예산에 포함했다. 자동 재시도하지 않으며 callback 성공 뒤
  정리 실패는 성공 결과를 유지한다. 저장소 고장까지 지속되면 재시작 후 영속성을
  완전히 보장하지 못한다는 한계를 이슈에 명시했다.
- 정책별 실패 기억과 명시적 전체 실패 기록 초기화를 구현했다. 일반 자동 새로고침은
  초기화하지 않으며, 새 버튼도 과거 queue/action을 재전송하지 않는다.
- 새 버전 검증 CLI·14개 회귀·한국어 사용법을 추가했다.
  명령 인자와 실행 조건은 아래 새 버전 검사 방법 문서에서 확인할 수 있다.
  CI 템플릿 초안은 별도 로컬 작업으로 이번 게시 범위에서 제외한다.
  GitHub 자동 스케줄은 별도 승인된 루트 workflow 통합과 원격 반영 전까지 동작하지 않는다.

### 2026-09-07 공식 Codex 복구·실런타임 검사

깨진 `/opt/homebrew/bin/codex` 링크의 목적지에는 본체만 없고 동반 파일은 남아 있었다.
제거 경위는 확인하지 못했지만, `brew reinstall --cask codex`로 0.153.4 공식 배포본
전체를 복구했다. 본체·host·rg·zsh·manifest 구성, 서명·공증, 정확한 버전, 실제 TUI
시작을 각각 확인했다. 이전 ENOENT 시나리오를 포함한 관련 Node 통합 테스트 10/10과
실제 호환성 CLI의 `smoke_passed`도 통과했다. 증거 파일은
`/private/tmp/blabee-codex-recovery-final-0907/qualification.json`이다.

### 2026-09-07 당시 미완료 운영 항목

0.153.4 Plugin CLI 운영 allowlist 추가와 검증용 Blabee 설치본 교체는 수행했다.
ad-hoc 앱의 background service 재등록, 실제 Pet 마우스 클릭, DMG 재생성,
원격 CI 활성화, 커밋·푸시는 아직 수행하지 않았다.
이후 2026-09-08에는 build 13의 앱 실행형 서비스 연결·종료·선택 왕복과 r14 DMG 제작을
별도로 검증했다. [r14 릴리스 기록](INTERNAL_DMG_R14_RELEASE_KO.md)을 최신 산출물 기준으로
사용한다. 이는 기존 background service 서명 장애 해결이나 다른 Mac 자격을 뜻하지 않는다.
[현재 이슈](KNOWN_ISSUES.md)의 `BLB-CODEX-UPDATE-001/002`와
[새 버전 검사 방법](CODEX_COMPATIBILITY_QUALIFICATION.md)을 함께 확인한다.
